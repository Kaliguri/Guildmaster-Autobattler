# UI-референсы — рабочая база

Не галерея красивого, а **опора для проектирования наших экранов**: из неё берутся раскладка,
размеры и приёмы, когда садишься за конкретный экран.

База переехала сюда из `docs/ui-refs/` 2026-08-03 вместе с методикой. Прежняя версия простояла с
16.07 по 03.08 с семью пустыми папками и нулём разборов — потому что разбирали «вообще», без
адресата. Здесь адресат есть: мы делаем экраны по этому материалу.

## Разделение труда

- **Макс** — вкус и насмотренность: кладёт картинки, называет ориентиры, держит визуальную приёмку.
- **Никси** — раскладывает, разбирает, меряет и сводит в выводы.

## Основные ориентиры

Два рефа считаются опорными — с ними сверяются раскладки новых экранов:

- **Guildrun** — жанровый сосед: тон, плотность, обращение с карточками и подсказками.
- **Heroes Olden Era** (с 21.08.2026, слова Макса: «Оч крутой реф, теперь это новый основной на
  уровне с Guildrun»). Десять кадров: главное меню, настройки, пауза, выбор профиля, выбор режима,
  карта, победа, три карточки обучения. Разобраны в `01`, `02`, `03`, `05`, `06`.

Копировать их нельзя (решение по Guildrun от 03.08.2026: «это слишком плагиат») — берётся ФОРМУЛА:
раскладка, доли, приёмы состояний.

## Методика разбора

Разбор пишется **на класс экрана, а не на картинку**. Это главное правило: ценность базы не в
отдельном рефе, а в сравнении внутри класса — «так делают одиннадцать из четырнадцати, а эти двое
ломают схему и вот чем платят». Разбор одной картинки такого не даёт никогда.

Оси разбора: инвентарь элементов → раскладка и сравнительная таблица по играм → размеры и ритм
→ стиль и цвет → состояния → приёмы → чего избегать.

Три правила, без которых разбор превращается в мнение:

1. **Каждое утверждение — со ссылкой на файл.** «Логотип в верхней трети (9 Kings, Brotato,
   Hades II)». Без источника утверждение не пишется вообще.
2. **Размеры — только в долях экрана.** Рефы 1280×720, игра 1080p+; переносимы проценты, а не
   пиксели.
3. **Цвет — замером, а не глазами.** Словесное «тёмно-синяя панель» в токены не кладётся.

Анти-цель — «мне нравится». Цель — «приём X, вот куда применить».

## Замер палитры

```powershell
python scripts/ui-ref-palette.py
```

Пишет `_teardowns/00-palette-measured.md`: доминирующие цвета с долями, взвешенная светлота и
насыщенность, доля тёмного и **акцентный цвет** — кайма или подсветка, ради которых всё и меряется.

Две готчи, обе стоили по итерации:

- Акцент ищется прямым проходом по насыщенным пикселям, а НЕ в квантованной палитре: кайма занимает
  доли процента площади, и квантование её просто не видит — в палитру попадают фон, панель и текст.
- У почти чёрного цвета насыщенность в HLS математически высокая при нулевой яркости, поэтому без
  вилки по светлоте акцентом каждый раз оказывался фон вида `#020103` с `s=0.50`.

Ограничение, которое надо держать в голове: скрипт меряет **весь кадр**, поэтому на боевых HUD в
замер попадает мир, а не интерфейс. Меряя панель, задавай область:

```powershell
python scripts/ui-ref-palette.py --crop 960,120,1280,600 --files "TFT HUD.jpg"
```
