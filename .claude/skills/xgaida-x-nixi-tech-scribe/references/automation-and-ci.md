# Автоматизация: дашборд, гейт ссылок, CI

Читать при работе с дашбордом готовности, проверке ссылок, настройке CI. Здесь — что
заведено, как гонять, как устроено.

## Dataview-дашборд готовности

В `00-meta/index.md` (MOC) — авто-сводка по frontmatter. Требует community-плагин
**Dataview** (установлен в vault). Рендерится **только в Obsidian** — визуальная приёмка за
Максом, не за мной (в git это просто текст code-fence).

Два блока:

```dataview
TABLE length(rows) AS "Доков"
FROM "tech"
WHERE file.name != "index"
GROUP BY status AS "Статус"
SORT key ASC
```
```dataview
TABLE status AS "Статус", updated AS "Обновлён"
FROM "tech"
WHERE (status = "needs_review" OR status = "draft") AND file.name != "index"
SORT updated ASC, file.name ASC
```

- `FROM "tech"` — путь от корня vault (**vault root = `docs/wiki`**, там лежит `.obsidian`).
  Не `docs/wiki/tech` — это было бы `docs/wiki/docs/wiki/tech`.
- Первый блок — «сколько доков в каждом статусе» (обзор готовности).
- Второй — «что требует внимания» (needs_review/draft), отсортировано по дате.
- Легенда статусов — внизу MOC.

## Гейт битых ссылок: `scripts/check-wiki-links.ps1`

Obsidian-aware проверка целостности внутренних ссылок по всему vault. Гоняется и локально
(Windows/`pwsh`), и в CI (ubuntu/`pwsh` — предустановлен на раннерах).

```powershell
./scripts/check-wiki-links.ps1 -VaultPath docs/wiki
```

Exit 0 — битых нет; exit 1 — есть (печатает список `файл -> ссылка`). Прогонять **после
любого переноса/переименования** (правило 4 SKILL).

### Как резолвит (правила Obsidian)

- **markdown `[..](path)`** — относительно ПАПКИ файла-источника; нормализует `../`; выход
  за корень vault считается внешней ссылкой (пропуск).
- **wiki `[[a/b/c]]` с `/`** — partial-path: существует файл, чей путь от vault равен или
  оканчивается на `a/b/c(.md)`.
- **wiki `[[name]]` без `/`** — короткая ссылка по имени файла (basename).
- **Код** внутри fenced ```` ``` ```` и inline `` `..` `` не парсится (Obsidian там ссылки
  не рендерит) — иначе `[[wikilinks]]`-примеры в доке про синтаксис ложно срабатывают.
- Внешние (`http`/`mailto`/`obsidian`), чистые якоря (`#..`), абсолютные пути, ссылки на
  директории (trailing `/`) — обрабатываются корректно (не ложно-битые).

### Что гейт вскрывает (кроме своих переносов)

На заведении (2026-07-16) поймал давние болезни vault: одинарный `../gdd/` вместо `../../gdd/`
(Фаза 1 не обновила глубину при переносе в кластеры), переименованный `.base`-файл, stale
`[[tech/0.0. README]]`, и 15 висячих `[[...]]` на несуществующие заметки (слаги приватной
памяти + заготовки). Висячие расплетены в текст — **приватные memory-слаги не должны
попадать на публичный Quartz-сайт**. Урок: vault-доки ссылались на memory-файлы, а память ≠
vault (никогда не резолвится).

## CI: `.github/workflows/docs-lint.yml`

Блокирующий гейт: `pull_request` + `push` в `dev`/`master`, по путям `docs/wiki/**`,
`scripts/check-wiki-links.ps1`, сам workflow. Один job на `ubuntu-latest`, `shell: pwsh`,
гоняет скрипт. Красный гейт = битые ссылки = PR не проходит.

Отдельный от `docs.yml` (Quartz+Doxygen деплой) — линт не связан с деплоем и должен бежать
на PR, а не только на push.

## Doxygen / API-справка — ВНЕ этого скилла

Автоген API из C#-докстрингов — **отдельный инфра-контур** (`docs.yml` собирает Doxygen +
Quartz на Pages; см. `30-how-to/docs-site.md`). tech-scribe ведёт **рукописную** markdown-
доку; смешивать автоген и рукопись в одном контуре = размытые границы. Здесь только
упоминаем связь: explanation может ссылаться на сгенерированную API-справку, но не порождает её.
