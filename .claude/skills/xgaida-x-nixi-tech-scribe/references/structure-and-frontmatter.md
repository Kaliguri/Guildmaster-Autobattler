# Структура, frontmatter и порядок без поломки ссылок

Читать при реорганизации, заведении нового tech-дока, смене порядка/статуса, переносе.
Здесь — целевая раскладка и механика «переставлять, не ломая ссылки».

## Ключевая идея: отвязать ПОРЯДОК от ИДЕНТИЧНОСТИ

- **Идентичность** = стабильный латинский слаг в имени файла (`assemblies.md`). Не меняется
  при переупорядочивании → ссылки вечны.
- **Порядок** = поле `order` во frontmatter (число). Сменить порядок = поправить YAML,
  файл не трогается.
- **Человеческое имя** = `title` по системе `Cluster - Name` (EN). Obsidian/Quartz
  показывают `title`, git/URL/агент видят слаг.

## Diátaxis-кластеры (папки нумерованы)

Четыре кластера (после расформирования `20-explanation` 30.07.2026), папки нумерованы для порядка:

```
docs/wiki/tech/
  00-meta/         служебное: index (MOC + дашборд) · journal/ · tech-debt · tech-changelog (архив)
  10-reference/    сухие факты «как есть» (что где, какие сигнатуры, какие правила)
  30-how-to/       решить конкретную задачу (setup, добавить ассет, собрать сайт)
  40-planning/     планы и роадмап (АРХИВ замысла по фазам)
```

> [!important] С 30.07.2026 состав кластеров изменён
> Описания ниже — про **каркас** (как устроены папки и frontmatter), он в силе. Но доки, которые
> пересказывали код, **удалены**: `20-explanation` расформирован целиком, из `10-reference` ушла
> описательная часть. Живы `00-meta/journal/`, `tech-debt`, `30-how-to` и предписывающие доки
> `10-reference`. Правда о коде живёт в коде — см. SKILL.md.
>
> **Запись журнала — исключение из схемы frontmatter ниже:** ровно `title`, `date`, `tags`, без
> `order` и `status` (порядок из имени файла, статус к историчной записи не применим).

**Что вообще заводить в `10-reference`:** только то, что код **предписывает** — конвенцию, шкалу,
правило меню, палитру, — либо генерируемый реестр. Описание того, как код работает, в вики не
заводится вовсе: это `<summary>`/`<remarks>` и Doxygen. Обоснование решения — запись в `journal/`.

Нумерация папок задаёт Diátaxis-порядок в Obsidian-эксплорере (иначе алфавит ставит
`reference` в хвост). `00-meta` первым (служебное сверху), дальше 10→40 по «читательскому»
порядку: сначала факты, потом объяснения, потом задачи, потом планы.

## Frontmatter-схема tech-дока

```yaml
---
title: "Reference - Assemblies"   # EN, система Cluster - Name
order: 10                         # порядок внутри кластера (шаг 10)
status: ready                     # см. легенду
updated: 2026-07-16
---
```

Система тайтлов (EN, `<Cluster> - <Name>`, как во всём vault): кластер — ярлык папки
(`Reference`, `How-to`, `Planning`, `Meta`, `Journal`). Обзорный файл не дублирует префикс.

## Легенда статусов (финальные 6)

- `draft` — набросок, не сверен.
- `needs_review` — готов, но нужна сверка с кодом / глаз Макса.
- `ready` — актуально, сверено с кодом.
- `planned` — план на будущее, реализации ещё нет (напр. `seed`, `steam-workshop`).
- `living` — вечно живой (roadmap, changelog) — «готовность» к нему не применима.
- `archive` — исторический (снятое, легаси).

Статус в frontmatter — источник; если в теле дока есть строка `**Статус:**`, она обязана
совпадать с frontmatter (иначе рассинхрон, который читатель видит первым).

## MOC + дашборд вместо голых таблиц

`00-meta/index.md` — живой Map of Content: сгруппированные по кластерам `[[ссылки]]` с одной
строкой контекста и ярлыком статуса, **плюс Dataview-дашборд готовности** (см.
`automation-and-ci.md`). Обновляется при добавлении/переносе дока. Легенда статусов — внизу MOC.

## Механика переноса без поломки ссылок

- **Если переносит Макс из Obsidian** — настройка *Files & links → Automatically update
  internal links* авто-чинит `[[wikilinks]]` и markdown-ссылки.
- **Если файлы двигаю я (git mv / FS)** — Obsidian не в курсе, чиню ссылки сама:
  1. `git mv` файла/папки (сохраняет историю).
  2. Массовый `grep -rl` старого пути **по всему vault** (не только tech/), `sed` на новый.
     Ловить оба формата: `[[путь/слаг]]` и markdown `[текст](путь/слаг.md)` (+ `%20`-энкод).
  3. Обновить MOC (`index.md`): и ссылки, и текстовые подписи путей в заголовках секций.
  4. Прогнать `check-wiki-links.ps1` — 0 битых.
- После нумерации/слагов будущие переносы дёшевы: порядок правится `order`, слаг стабилен.

## Пример из практики (миграция 2026-07-16)

Нумерация папок `reference→10-reference` и т.д. тронула пути всех 34 доков и ~200 ссылок.
Безопасно прошло так: `git mv` папок → `sed` по всему vault (4 замены путей) → правка
текстовых подписей в MOC → `check-wiki-links.ps1` = 0 битых (36 tech-целей, 128 .md). Гейт
тогда же вскрыл 14 давних миграционных битых (одинарный `../gdd/` вместо `../../gdd/` после
переноса в кластеры Фазой 1) — их и чинили в тот же заход.
