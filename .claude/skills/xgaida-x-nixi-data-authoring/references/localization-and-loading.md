# Локализация и загрузка контента

Читать перед правкой player-facing текста или схемы загрузки ассетов.

## Лок-ключи: конвенция, не поля

Player-facing текст НЕ хранится в SO — он живёт в String Table `Content` (Unity Localization),
ключи выводятся из id по конвенции. `Assets/_Project/Scripts/Data/Editor/ContentLocalization.cs`
держит ЕДИНУЮ политику (её же берёт валидация, чтобы «что создаём» и «что проверяем» не разъезжались):

- `TableName = "Content"`, суффиксы `name` / `desc`.
- `KeyFor(def, suffix)` = `{def.Id}.{suffix}` → `relic.cryomancer.name`, `relic.cryomancer.desc`.

**Обязательные суффиксы по домену** (`RequiredSuffixes`):

| Домен | Ключи | Почему |
|---|---|---|
| `tag`, `ai_preset` | нет | техническая таксономия / ИИ, игроку не видны |
| `encounter`, `battle_preset` | нет | dev-конструкты; получат name/desc, когда станут узлами карты |
| `event` | `title`, `body`, `choice{i}.label`, `choice{i}.result` | весь текст ивента ключами из id; число вариантов — из ассета |
| `effect` | `name` всегда; `desc` только если есть иконка | desc виден в бафф-баре лишь у эффекта с иконкой |
| прочее | `name` + `desc` | обычный player-facing контент |

Новый контент-тип с текстом → реши его политику суффиксов в `RequiredSuffixes` (а не хардкодь
ключи в другом месте).

## RU-only, прочие локали прочерк

Проект локализуем EN + RU, но **заполняем сейчас только RU**; остальные локали — прочерк (пустая
запись). Ключи закладываются сразу и всегда — ретрофит локализации дорогой, заведение ключа дешёвое.

Editor-хелпер (`ContentLocalization`):
- `MissingKeys(def)` — обязательные ключи ассета, которых ещё нет.
- `CreateMissingKeys(def)` / `CreateMissingKeysForDomain(type)` — завести недостающие ключи (по
  ассету / по всему домену).
- `GetValue`/`SetValue(localeCode, key, value)` — чтение/запись по локали (заводит общий ключ и
  запись при отсутствии).

Авторя контент с текстом: завёл ассет → `CreateMissingKeys` → заполнил RU-значения. Прямую строку в
поле SO не клади — это откат к нелокализуемому тексту (HARD-правило 5).

## Загрузка контента: прямые ссылки, Addressables только под Loc

- **Контент — прямые ссылки** через `ContentDatabase` → `ContentRegistry` (VContainer
  `RegisterInstance`). Compile-time safety, ноль async-сложности.
- **Addressables — только плумбинг Unity Localization.** НЕ смешивать прямые и addressable-ссылки на
  один ассет: это дублирует его в билде («Unfixable»-предупреждение).
- Обязательно в билде: **Build Addressables on Player Build** — иначе пустые переводы в CI-сборке.

## Когда пересматривать (триггеры)

Прямые ссылки — правильный дефолт сейчас (ростер маленький). Пересмотр в сторону
Addressables/AssetBundle — при появлении конкретного триггера, не «на будущее»:

1. **Моды/Steam Workshop переходят из «планируем» в «делаем».** Мод везёт контент вне билда игрока —
   это практически требует динамической загрузки. Самый вероятный триггер (см. source-namespace шов
   в `three-layers-and-ids.md`). На сейчас — планируется, но не скоро.
2. **Арт переваливает ~0.5 ГБ** и время билда/загрузки начинает болеть.
3. **Remote-контент / патчинг** появляется в плане.

Пока триггеров нет: держи весь доступ через `IContentDatabase` (это и есть точка будущего
переключения) и не раздавай прямых SO-ссылок из геймплея. Тогда switch останется локальным.
