# Статы и конфиги

Читать перед правкой статов юнита, стат-системы или конфиг-SO.

## Список статов (StatType)

`Assets/_Project/Scripts/Data/Stats/StatType.cs` — канонический список ровно 30 статов, источник
правды — вики «11. Стат-система». **Порядок и номера enum менять НЕЛЬЗЯ** (Unity сериализует enum по
int — сдвиг сломает все .asset). Новый стат — только в конец с явным номером.

Натуральные дефолты по смыслу стата (`StatsConfig.NaturalDefault`): `1.0` для PercentMult-
эффективностей (`DamageTakenEff`, `DamageDealtEff`, `*Eff`) и `Size`; иначе `0`.

## StatModifier / ModifierOp

`StatModifier.cs` — `{ StatType Stat; ModifierOp Op; float Value; }`, сериализуемый: годится и для
авторинга стат-блока на SO, и как рантайм-нагрузка для `Stats`. Источник (для снятия разом) в
модификаторе НЕ хранится — им управляет рантайм `Stats` как ключом группировки.

`ModifierOp.cs` — операции и формула сборки:

```
final = (baseTerm + ΣFlat) × (1 + ΣPercentAdd) × Π(1 + PercentMult)
baseTerm = Override (если задан) ИНАЧЕ дефолт StatsConfig
```

| Op | Смысл |
|---|---|
| `Flat` | плоская прибавка к базе (складывается) |
| `PercentAdd` | аддитивный процент — всё в одну скобку `(1 + Σ)` |
| `PercentMult` | мультипликативный — каждый множитель отдельный `(1 + x)`, перемножаются |
| `Override` | абсолютный ввод: ЗАМЕНЯЕТ базовый терм; при нескольких — побеждает последний |

## Авторинг базы через Override — это КАНОН, не костыль

Базовые статы юнита авторятся как **абсолют через `Override`** в `UnitData._stats`
(`StatModifier[]`): реликвия задаёт реальное значение стата (HP = `{MaxHP, Override, 1800}`), а не
дельту от дефолта. `StatsConfig` остаётся фолбэком для НЕзаданных статов и стартовой GD-напоминалкой
при создании SO.

Это осознанное рабочее решение (`ModifierOp.Override` док: «Основной способ авторинга базовых статов
юнита»), а не обходной путь:

- База концептуально и есть «замени дефолт на это абсолютное значение» — семантика связна.
- Один список `_stats` держит и базу (`Override`), и дельты реликвии (`Flat`/`Percent`) — их легко
  разделить фильтром по `Op`, если инструменту нужно.
- Система собирает `база + модификаторы` корректно (`Stats.RebuildCache`), покрыта боевыми
  EditMode-тестами.

**Не «улучшай» это в отдельный BaseStats-блок без явной причины.** Ревизию рассматривали и отклонили
как оверинжиниринг: payoff мал (читаемость, которую и так даёт Content Hub), а цена — миграция всех
ассетов + правка `Stats.cs`/фабрики + риск на работающей системе. Триггер пересмотра — только
РЕАЛЬНАЯ боль авторинга (путаница базы и баффов в одном списке, копящаяся на сотнях юнитов), а не
эстетика.

## Сборка статов в рантайме (Stats.cs)

`Assets/_Project/Scripts/Combat/Stats/Stats.cs` (владелец — combat-sim; контракт данных — здесь):

- `AddModifiersFrom(source, StatModifier[])` / `RemoveModifiersFrom(source)` — модификаторы
  группируются по источнику, снимаются разом (реликвия, бафф, аура).
- `RebuildCache` считает по формуле выше, кэширует, инвалидируется dirty-флагом.
- `baseTerm = Override (если задан) ИНАЧЕ config.GetDefault (или NaturalDefault, если config == null)`.
- Фабрика (`RuntimeUnitFactory`) скармливает `UnitData.Stats` как группу от источника-`UnitData`.

Авторя данные, помни: твой `Override` в SO становится базовым термом, поверх которого затем работают
`Flat`/`Percent` от бафов и эффектов. Рут «MoveSpeed = 0» — это рантайм-`Override` от эффекта, он
законно бьёт базу.

## StatsConfig: глобальный шаблон

`Assets/_Project/Scripts/Data/Definitions/StatsConfig.cs` — единственный экземпляр на проект:

- `ArmorConstantK` (пайплайн урона `mult = K / (K + effArmor)`), клампы скорости атаки
  (`AttackSpeedMin/Max`).
- `GetDefault(stat)` — явный override из массива `_defaults` ИНАЧЕ `NaturalDefault`.
- Это фолбэк и тюнинг-константы, НЕ место для базы конкретных юнитов (та — в их SO).

## Конфиг-бейк и live-тюнинг

- Сим работает со **снапшотом**, снятым на старте боя, — не дёргает SO в тике.
- `TickRate = 30` и подобные — **константы кода** (`SimConstants`), не ручки в ассете.
- **Live-тюнинг** = правка SO в play mode (персистится — это фича) + явный re-bake с пометкой боя
  `tainted`. Дефолт живёт в `.asset`, не в инициализаторе поля: правка инициализатора НЕ обновляет
  существующие ассеты.
- **Кривые бейкаются в таблицы** — `AnimationCurve.Evaluate` из тика сима запрещён (недетерминизм,
  прецедент Photon Quantum). Авторишь кривую в SO — она должна пройти bake в массив на старте.

## Анти-хардкод

Тюнеры и статы — из данных, не магические числа в коде: боевые тюнеры — `SimTuning` (dev-`gm_*`),
статы — стат-блок SO + `StatsConfig`, feel — `CombatFeelConfig`. Число в коде = двойная работа при
балансе и рассинхрон между «как задумано» и «как считается».
