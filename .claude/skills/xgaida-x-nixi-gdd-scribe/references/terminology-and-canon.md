# Термины и канон-дома

Читать при работе с терминами и при разносе решений. Здесь — где живёт правда о термине и
какой факт принадлежит какой главе (single source).

## Глоссарий — источник правды о терминах

`docs/wiki/gdd/0.4. Локализация.md` — таблица `RU | EN | Сокращение | Примечание`. Единый
глоссарий для UI, кода и доков. Уже вяжет термины с кодом (напр. Перк/**Trait** →
`TraitData`, Последствие/Consequence → `ConsequenceData`). Нормативные теги
(school/affinity/creature_type, роли) — `docs/wiki/gdd/roster/Справочник тегов.md`.

**Правило:** новый термин — сперва строку в `0.4` (RU/EN/примечание), потом в текст.
Меняешь смысл термина — правишь глоссарий, затем прогоняешь употребления. Не плодить синоним.

## EN-канон для сущностего

Мементо/Арканы, id, названия контента — **по-английски** (`The Pyre`, `Goblin Grunt`,
`Faction - Bandits`). Эталон единообразия — папка `enemies/`. В `relics/` есть легаси-микс
(часть карточек ещё по-русски) — при касании приводить к Arcana-канону.

## Известные рассинхроны (следить, чинить при касании)

- «Обычная» на двух осях: редкость (Треш/Обычная/Уник) vs тип мементо (Стандартная).
  В глоссарии уже разведено («Стандартное Мементо — не путать с редкостью Обычная») —
  держать это разведение в главах.
- Перк vs Trait vs Талант/Perk — канон `Trait`, остальное легаси.
- Легаси-стихии (Вода/Ветер/Земля/Разум) в старых шаблонах — не канон.

## Карта канон-домов (какой факт где живёт)

Single source: у каждого факта ОДИН дом. При разносе решения обновляй дом, из остальных мест
ссылайся, не копируй.

| Тема | Канон-дом (глава) |
|---|---|
| Модель урона: школы/сродства/2 брони/True | `combat-system` + `stats` + `effects` |
| Каталог эффектов, идентичность стихий, комбо | `effects` (`15. Система эффектов`) |
| Статы: словарь и смысл | `stats` (`8. Статы`) |
| Типы боёв, фазы, цели боя, перезапуск | `combat-system` (`3. Боевая система`) |
| Травмы/Закалка (Consequence) | `injuries-mettle` (`9. Травмы и Закалка`) |
| Экономика забега, реворд-ramp, левел мементо | `meta-progression` (`12. Мета`) |
| Мементо: редкость/типы, Судьбы, перки | `relics-overview` (`5. Мементо`) + карточки `relics/` |
| Предметы и Знамёна, слоты, авто-триггеры | `items-banners` (`16. Предметы и Знамёна`) |
| Ивенты, мини-игры, карта | `events-minigames` (`7. Ивенты`) |
| Кооп, распределение «Сосудов» | `multiplayer` (`6. Мультиплеер`) |
| Термины | `glossary` (`0.4`) + `Справочник тегов` |
| Снятые механики | `legacy` (`0.5`) |

Спорный факт «живёт на два дома» (напр. модель урона касается боя, статов и эффектов):
выбрать ГЛАВНЫЙ дом (где полная формулировка), в остальных — короткая ссылка `[[...]]`, не дубль.

## Связь с кодом

ГДД ссылается на реальные типы: `TraitData`, `ConsequenceData`, `RunModifierData`,
`ItemData`, `BattlePresetData`, `RelicRarity`, компоненты эффектов (`PeriodicDamageComponent`).
Карточки контента несут YAML (`kind/status/rarity/…/needs_review`). Это стык с
data-authoring: ГДД описывает ДИЗАЙН и ссылается на тип; сам SO/id/значения — территория
data-authoring. Loc-ключи для нового текста закладываются при авторинге (RU заполнен).
