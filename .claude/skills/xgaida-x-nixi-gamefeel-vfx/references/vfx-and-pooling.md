# VFX: префаб-шов, пул, точки-сокеты

Читать перед созданием или правкой VFX. Ключевой инвариант скилла: **все VFX — префабы**.
Кодовый меш — placeholder-долг, не образец.

## Эталон уже в проекте: `UnitData.ViewPrefab`

Правильный data-driven VFX-шов уже работает для видов юнитов и снарядов:

- `UnitData.ViewPrefab` — самодостаточный префаб персонажа (визуал/анимация/размер настроены
  ПРЯМО в нём). `CombatPresenter.HandleUnitSpawned` инстанциирует его: «Никакой рантайм-подмены
  визуала — префаб самодостаточен».
- `_bulletPrefab` (снаряд), `_floatingTextPrefab` (боевая цифра) — тоже префабы: `Instantiate` /
  `ObjectPool`.

Новый VFX — зеркало этого: SO держит ссылку на префаб, презентер спавнит его в точке.

## Шов ПОСТРОЕН (не проектируем — пользуемся)

1. **`VfxData` SO** (`Data/Definitions/VfxData.cs`, владеет `data-authoring`): `id` (`domain.name`),
   ссылка на VFX-префаб, sorting layer/order, `DefaultDirDeg`.
2. **`CombatVfx`** (`Presentation/CombatVfx.cs`) — пул и спавн префабов (`PooledVfx`). Sorting и
   default-dir берутся из `VfxData`, относительный order детей — из самого префаба. **Ключ пула —
   `EntityId` префаба, а не `int`:** приведение `EntityId` к `int` Unity объявила уходящим.
3. **Проводка по событию** — презентер резолвит `VfxData` и просит `CombatVfx` проиграть в мировой
   точке-сокете; направление можно переопределить, `null` → `VfxData.DefaultDirDeg`.

Владение `VfxData`-определением — `data-authoring` (id, поля, loc), спавн-механика — здесь.

## Точки-сокеты — из вида, не из позиции сима

Мировые якоря спавна берём с `UnitView`, а не из `RuntimeUnit.Position` (сим стреляет/бьёт из
центра, а визуально эффект нужен из дула/груди/ног):

- `ShotPoint` — дуло (muzzle, старт снаряда/выстрела).
- `HitPoint` — грудь/точка попадания (искры, хил, боевая цифра).
- `FeetPoint` — ноги (пыль от мили-удара).
- `BodySortingLayerId`/`BodySortingOrder` — чтобы VFX лёг поверх/под тело (сортировка задаётся
  относительно тела: `+5` над, `-1` под).

Фолбэк, если вида цели нет: позиция сима + небольшой офсет вверх (см. `AnchorFor` в презентере).

## Пул — обязателен, zero-alloc в бою

Бой спавнит фидбэк каждый кадр — без пула это GC-давление. Паттерн (`CombatVfx.Initialize`):

- Лениво создать `ObjectPool<T>` (первый спавн), `collectionCheck: false`, разумные
  `defaultCapacity`/`maxSize`.
- `Get()` → активировать → `Play(..., release-callback)`; эффект сам зовёт `release` по завершению.
- При `OnBattleReset` — вернуть/погасить всё летящее (иначе висит в новом бою; см. как презентер
  чистит `FloatingText` через `Cancel()` и уничтожает виды снарядов/трупы).

## Что ещё строится кодом (и почему это не приглашение)

`PixelBurst` / `PixelBurstMesh` / `PixelBurstPreset` **удалены** — пиксельные брызги переехали на
префаб-пул выше. Если встретишь эти имена в старых доках или обсуждениях, они мертвы.

Кодом сейчас строятся два места, и у обоих причина не «не дошли руки»:

- `DeathShatter` / `ShatterMesh` — разлёт спрайта на треугольники-осколки при смерти. Меш режется из
  того самого спрайта, который был на юните, поэтому префабом это не подменить: геометрия зависит от
  вида конкретного юнита.
- `CombatStatusOverlay` — dev-слой статус-колец. Живёт до нормального UI статусов; **не** визуальный
  язык игры.

**Новый эффект кодовым мешем не делаем** — только `VfxData` + префаб + `CombatVfx`.

## Антипаттерны

- **Новый VFX кодовым мешем «на время».** Долг не растим. Нет префаба/арта — заводим заглушку-
  префаб и шов, а не ещё один `AddComponent`-эффект.
- **Спавн без пула.** `Instantiate`/`Destroy` каждый удар = GC-спайки в бою.
- **Якорь из `RuntimeUnit.Position`.** Визуальный эффект — из точки-сокета вида; позиция сима —
  только фолбэк.
- **VFX, переживающий рестарт.** Всё летящее гасим по `OnBattleReset`.
- **Параметры VFX в коде.** Формы/цвета/тайминги — в SO (сейчас `CombatFeelConfig`, дальше
  `VfxData`).
