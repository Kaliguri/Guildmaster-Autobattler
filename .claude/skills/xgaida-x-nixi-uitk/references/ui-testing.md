# UI-тесты: клики и смоук-проверки

Автоматическая проверка интерактивного UI через официальный пакет
`com.unity.ui.test-framework` (`PanelSimulator`). Даёт не-визуальный сигнал — «нажал →
состояние поменялось», — которому можно верить, не гоняя Макса на ручную проверку.

Это закрывает единственный сценарий, ради которого был соблазн тащить сторонний
`unity-cli`: клики по UITK-элементам решаются штатным пакетом внутри нашего же
тест-пайплайна (`run_tests`), без второго моста в Unity.

## Установка

Пакет `com.unity.ui.test-framework` — через Package Manager (Add package by name) или
`Packages/manifest.json`. После установки — `read_console` на ошибки компиляции.
Тесты кладём в PlayMode-сборку: `Assets/_Project/Tests/PlayMode/`
(`Guildmaster.Tests.PlayMode.asmdef`), добавив ссылку на тест-фреймворк в asmdef.

## Паттерн смоук-теста

`PanelSimulator` шлёт синтетические pointer-события в реальное дерево панели:

```csharp
// 1. Поднять панель (через превью-стенд или UIDocument сцены), получить rootVisualElement.
// 2. Обновить кадр, дать layout устаканиться:
simulate.FrameUpdate();

// 3. Достать контрол и кликнуть:
var button = root.Q<Button>("btn-save");
simulate.Click(button);              // pointer down → up на элементе = ClickEvent

// 4. Проверить СОСТОЯНИЕ (не пиксели): изменилось ли то, что должно.
Assert.IsTrue(vm.Saved);
```

Ключевое:
- `simulate.FrameUpdate()` перед взаимодействием — иначе layout ещё нулевой и клик
  промахнётся.
- Есть `Click(VisualElement)` и `Click(Vector2)`; для двойного — соответствующий вызов
  с `clickCount`.
- Для событий вне абстракции — ручной синтез через `UnityEngine.Event` +
  `panel.visualTree.SendEvent()`, но начинай с `PanelSimulator`.

## Что тестировать

Проверяем **состояние и проводку**, а не внешний вид:
- Клик по «Сохранить» → VM сохранил, baseline сдвинулся.
- Клик по «Отмена» → значения откатились к baseline.
- Драг слайдера → VM получил новое значение; обратное `SetValueWithoutNotify` не
  зациклило события.
- Переключение таба через роутер → активна нужная страница (`--active`/`--hidden`).

Внешний вид (масштаб, вёрстка, цвет) остаётся за визуальной приёмкой Макса — автотест
это не подменяет. Тесты — под реальное поведение и ГДД; краснеет — чини код или тест,
не ослабляй механику ради зелёного.

## Область

Внедряем сейчас, но начинаем узко — смоук-тесты ключевых интерактивных экранов
(настройки, лоадаут). Тяжёлая e2e-автоматизация (AltTester/GameDriver) — оверкилл для
объёма нашего UI, не тащим.
