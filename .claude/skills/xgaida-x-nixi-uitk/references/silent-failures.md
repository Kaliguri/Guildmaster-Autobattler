# Где UI Toolkit молчит

**Один принцип на весь файл: движок не показывает ошибку — он показывает нормально выглядящий
экран без части твоих правил.** Ни в консоли, ни при импорте USS, ни в тестах ничего не появится.
Поэтому «ошибок нет» никогда не значит «применилось»: проверка — это ЗАМЕР (`resolvedStyle`,
`worldBound`) или кадр, а не тишина в консоли.

Класс собран из журнала решений за август 2026 — каждая строка однажды стоила сессии.

## Стиль применился не весь

| Что молчит | Как выглядит | Чем ловится |
|---|---|---|
| **Неизвестный токен в `var(--…)`** — движок отбрасывает ВСЮ декларацию, без фолбэка и предупреждения | элемент просто не нарисован: нет подчёркивания вкладки, невидим фокус, ручка скроллера отсутствует | гейт ссылок против `tokens.*.uss`; четыре таких места прожили в дереве месяцами |
| **Битый комментарий USS** (`\* … */` вместо `/* … */`) — файл импортируется без ошибок и молча роняет ВЕСЬ ярус переменных | тема «не применилась», при этом `m_ImportedWithErrors=False` и парсер цел | чтение `resolvedStyle` конкретного элемента; консоль тут даёт зелёный свет на сломанной теме |
| **Вертикальные проценты считаются от ШИРИНЫ родителя** (правило CSS, унаследованное Yoga) | `padding-top: 6%` даёт 115px вместо 65 на кадре 1920×1080 — ровно в 1.78 раза | сверка `worldBound` с ожиданием; в USS правило выглядит корректным |
| **`-unity-text-auto-size` без продвинутого генератора текста** игнорируется целиком | подписи не сжимаются, и вдобавок предупреждение в каждом кадре | из темы убрано; длинную локализацию лечим шириной кнопки, не кеглем |
| **Правка приватных полей рефлексией** живёт до следующего пересчёта стиля | «агент вернул старый цвет» — значение откатывается через кадр | `RegisterCallback<CustomStyleResolvedEvent>` переустанавливает; инлайновый `ve.style.*` этим не страдает |
| **В play mode Unity не переимпортирует ассеты** | `AssetDatabase.Refresh` отвечает успехом, USS в живую панель не приезжает | проверять `EditorApplication.isPlaying` ПЕРЕД «готово, смотри» |

## Поведение работает не так, как выглядит

| Что молчит | Как выглядит | Чем лечится |
|---|---|---|
| **`Build` экрана зовётся ОДИН раз, показывают экран много** | после первого закрытия экран «сломан»: команды выполняются, окно молчит, список застывает | подписки живут в `OnEnter`/`OnExit`, никогда в `Build` |
| **Пересборка списка съедает двойной клик** | «двойной клик не работает», хотя обработчик на месте | выбор строки переставляет класс подсветки, а не пересобирает список |
| **Контрол наследует состояния чужого контрола**, на котором построен | вкладка ведёт себя как кнопка: под курсором заливка пластины, разница «навёл / открыт» пропадает | гасить ЯВНО все состояния, которые определяет родительский контрол, а не только те, что меняешь |
| **`PreventDefault()` заменяется ДВУМЯ вызовами** | убрал устаревший метод, оставил `StopPropagation` — вернулся баг с уходом фокуса | `StopPropagation()` + `focusController.IgnoreEvent(evt)` |
| **Необязательный параметр вида у `Build`** | стенд собирает экран наполовину: у исхода нет сводки, у списка гильдий нет эмблем | данные вида обязательны, дефолты только у колбэков |

## Что из этого следует для процедуры

1. **После правки темы — замер, а не импорт.** Успешный импорт ничего не доказывает.
2. **После правки раскладки — `worldBound`, а не чтение USS.** Число в файле может быть верным, а
   результат — нет.
3. **После правки состояний — контактный лист.** Состояние нельзя увидеть на обычном скриншоте.
4. **После правки экрана — кадр экрана.** Пропавший кусок выглядит как «так задумано».

Полные разборы — в `docs/wiki/tech/00-meta/journal/` за 01–06.08.2026; здесь только то, что нужно
помнить ДО правки.
