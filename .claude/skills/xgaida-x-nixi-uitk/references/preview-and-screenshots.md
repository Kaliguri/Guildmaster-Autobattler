# Превью, скриншоты и чеклист размеров

Как показать UI в реальном масштабе и не сделать панель на пол-экрана.

> ## ⚠️⚠️ ГЛАВНОЕ ПРАВИЛО ЭТОГО ФАЙЛА: КАРТИНКА В ЧАТ КАЖДЫЙ РАЗ ⚠️⚠️
>
> **Любой ответ, где я говорю про то, как выглядит UI, ОБЯЗАН содержать свежий скрин
> КАК ИЗОБРАЖЕНИЕ в этом же ответе.** Не «я поправила слоты» текстом — а картинка, где
> видно поправленные слоты. КАЖДАЯ итерация (новая раскладка, фикс бага, «стало лучше»)
> = свежий скрин в чате.
>
> **Технически:** `Read` PNG-файла рендерит картинку — но заверши ход этим `Read` ПРЯМО
> ПЕРЕД финальным текстом (сделай его последним действием перед словами), чтобы изображение
> шло встык к сообщению и гарантированно попало пользователю в чат. Снять скрин «для себя»
> и только описать словами — ПРОВАЛ. Макс повторял это в гневе; это мой самый частый косяк.
>
> Порядок хода при показе UI: `собрать → снять PNG → Read PNG → текст с выводами`. Без
> среднего `Read` в конце — считай, скрина нет.

## Чеклист размеров (под 1920×1080, scale = 1)

Значения — из токенов `tokens.primitives.uss`, не из головы:

- Шкала отступов: `--gm-space-1..6` = 8 / 16 / 24 / 32 / 48 / 64 px.
- Шрифты: `--gm-font-sm/body/title/lg` = 22 / 26 / 34 / 48 px.
- Рамки: `--gm-border-1/2` = 2 / 3 px.

Проверки против гигантизма:
- [ ] Диалоговая панель не занимает больше ~40–50% ширины экрана без веской причины.
- [ ] Дев-панели/оверлеи — компактные, не растянуты на весь экран.
- [ ] Отступы кратны шкале `--gm-space-*`, а не произвольные.
- [ ] Типографика в пределах токенов; нет «плакатного» текста ради акцента.
- [ ] Ритм по сетке: одинаковые зазоры между однородными блоками (`--gm-gap-stack`).

Эталоны вкуса: Balatro / Hades — плотные, читаемые, без пустого раздувания.

## Превью-стенд (изоляция)

Для снятия отдельного экрана/компонента вне игровой сцены:
`Assets/_Project/UI/Dev/UiPreviewRoot.uxml` + `PreviewPanelSettings.asset`. Позволяет
поднять один View без всей боевой сцены. Общий подход — один View-класс на экран,
подставляемый в стенд.

## Снятие скриншота — канон (проверено 2026-07-16)

**Канон: Play mode + сам назначь RenderTexture + прокрути кадры через
`EditorApplication.Step()` + `ReadPixels`.** Это единственный метод, который под MCP
надёжно отдаёт честный 1920×1080 с реальным контентом. Точный рабочий рецепт
(`execute_code`, один вызов):

```csharp
// Предусловие: редактор в Play mode (manage_editor play).
var doc = System.Array.Find(
    UnityEngine.Object.FindObjectsByType<UnityEngine.UIElements.UIDocument>(UnityEngine.FindObjectsSortMode.None),
    d => d.gameObject.name == "UI Root");            // имя нужного UIDocument
var ps = doc.panelSettings;

var rt = new UnityEngine.RenderTexture(1920, 1080, 24, UnityEngine.RenderTextureFormat.ARGB32);
rt.Create();
ps.targetTexture = rt;

for (int i = 0; i < 10; i++) UnityEditor.EditorApplication.Step();   // ДЕТЕРМИНИРОВАННО крутит кадры

var prev = UnityEngine.RenderTexture.active;
UnityEngine.RenderTexture.active = rt;
var tex = new UnityEngine.Texture2D(rt.width, rt.height, UnityEngine.TextureFormat.RGBA32, false);
tex.ReadPixels(new UnityEngine.Rect(0, 0, rt.width, rt.height), 0, 0);
tex.Apply();
UnityEngine.RenderTexture.active = prev;

System.IO.File.WriteAllBytes("Assets/Screenshots/ui.png", tex.EncodeToPNG());
UnityEditor.AssetDatabase.ImportAsset("Assets/Screenshots/ui.png");

ps.targetTexture = null;                              // ОБЯЗАТЕЛЬНО вернуть, иначе экран уедет в текстуру
UnityEngine.Object.DestroyImmediate(tex); rt.Release(); UnityEngine.Object.DestroyImmediate(rt);
```

Читать PNG обратно через `Read` (это картинка) и прогнать self-QA. Фон панели-оверлея
прозрачный — доля непрозрачных пикселей ~5–10% при заполненном экране это норма, не пусто.

### Почему не остальные (проверено, не гадание)

- **`manage_ui render_ui` в editor mode** — назначает RT верного размера (1920×1080), но
  кадр выходит **пустой** (`hasContent=false`): UITK в editor-панель не рендерит контент.
- **`manage_ui render_ui` в play mode (two-call)** — ждёт `WaitForEndOfFrame`, а под MCP
  кадр между двумя вызовами не гарантированно проходит → застревает на
  `capture_in_progress`. Ненадёжно.
- **`EditorApplication.Step()`** — обходит проблему: форсит кадры принудительно
  (`frameCount` реально растёт), не завися от фокуса окна. После Step редактор встаёт на
  паузу (`isPaused=true`) — для статичного снимка это ок.

### Готча: Run In Background и тик кадров

`render_ui`/естественный player-loop под MCP тикают недетерминированно, если
`PlayerSettings.runInBackground = false` **и** окно Unity не в фокусе — play mode
подмерзает между вызовами. В проекте это **включено** (`runInBackground = true`, коммитим
в ProjectSettings). Но канонный Step-метод от этого не зависит вовсе — он и есть страховка.

Общий готч масштаба: **не снимать offscreen с ppp=1** — это обманный уменьшенный масштаб.
Скрин Максу всегда честный 1920×1080 (что Step-метод и даёт — RT ровно 1920×1080).

## Ритм отправки: по ходу, не пачкой в конце

Требование Макса: кидать снимки в чат **по ходу** работы, а не копить к финалу. Сделал
экран → показал → пошёл дальше. Короткая петля «показал → быстро подсказал → поправил»
экономит время обоим. Не описывать словами — показывать картинку.

## Сама разглядывай рендер (self-QA), а не просто пересылай

Дизайн-система гарантирует консистентность, НЕ красоту. Перед отправкой открой PNG как
картинку (через `Read`) и прогони чеклист — ты ловишь баги сама, не перекладывая на
Макса первую линию:

- [ ] **Один шрифт семейно** — заголовок и тело/кнопки не разными гарнитурами (дрейф на
      LiberationSans = отсутствует токен шрифта).
- [ ] **Primary-кнопка латунная и заметнее вторичной** — не серая/«сломанная».
- [ ] **Нет протёкших сырых id и loc-ключей** на экране (`assassin`,
      `event.wandering_merchant` — это баг, не текст).
- [ ] **Панель не выше своего контента** — нет мёртвой пустоты и двойных рамок.
- [ ] **Обрезки текста не превращаются в бессмыслицу** (`assas…`).

Если что-то из этого видно — чини КОРЕНЬ в ярусах токенов/компонентов, не заплаткой по
месту. Частые корни рецидивов: нет токена шрифта (фолбэк на LiberationSans), серая
primary, протёкшие id/ключи.

Скрин(ы) экрана в реальном масштабе, уже прошедшие self-QA выше. Визуальную приёмку
делает Макс; моя работа — довести до «смотри, вот так выглядит», сама выловив явные
баги и не присылая искажённый масштаб.
