## Агент против скилла

Не конкуренты, складываются. **Скилл — знание и процедура**, вливается в текущий контекст: голова
та же, помнит разговор. **Агент — отдельная голова со своим окном**: возвращает вывод, а всё
прочитанное по дороге в основной контекст не попадает. Агент внутри себя может звать скилл — так и
задумано (`session-scout` работает поверх `xgaida-x-nixi-transcripts`).

## Когда заводить нового

Тот же дух, что у скиллов (`.claude/skills/BACKLOG.md`): под наблюдаемую боль, не «на будущее».
Плюс три условия, специфичных для агентов, — нужны все три:

1. **Вход много больше выхода.** Если ответ тоже простыня, делегировать нечего: простыня всё равно
   приедет в основной контекст.
2. **Вывод проверяем.** Агент возвращает якоря — `путь:строка`, id сессии, имя файла. Без них
   вызвавший обязан перечитать всё сам, и экономия обнуляется.
3. **Это поиск и сверка, а не суждение.** Агент не видит разговора, не может переспросить и
   возвращает уверенный ответ даже когда ошибся.

## Чего агентам не отдаём

- **Решения** — что делать с балансом, каким быть врагу, какая из двух архитектур живёт.
- **Правки кода пачками.** Если агент пишет, а мы пересказываем результат, отвечать за сданное
  некому; проектные HARD-правила агент нарушит молча.
- **Мелочь.** Каждый агент — отдельный прогон и стоит; задача на два грепа дешевле руками.

Отклонены осознанно: **чтец балансных отчётов** (выход почти равен входу, вердикт всё равно за
Максом) и **проверяльщик домов** (решения стали доезжать после хука компиляции и правила «запись в
журнал по коммиту» — боль ушла, агент остался бы без работы).
