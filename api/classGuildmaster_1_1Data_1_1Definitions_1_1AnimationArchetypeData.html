Detailed Description

АРХЕТИП АНИМАЦИЙ: набор клипов на AnimationClip-слотах — Idle/Run/Attack/Death/Hit, клипы скиллов, портрет.

Один архетип = одна хореография; «меч и щит», «копьё», «посох» будут разными архетипами при общем скелете.

Назывался UnitVisual до 06.08.2026, и имя врало: визуал — это спрайты, а здесь клипы. Переименовано по заказу Макса вместе с остальным неймингом фазы 0 (tech/40-planning/weapon-system §6.1).

Клипы отсюда НЕ подменяются override-контроллером, что бы ни говорил прежний докстринг: UnitView играет стейты контроллера по имени (Animator.Play), а этот набор служит источником МАРКЕРОВ и темпа. Сборка AnimatorOverrideController жила в покадровом пайплайне и удалена вместе с ним.

Живёт в Guildmaster.Data (не Presentation), потому что сим/фабрика считают windup авто-атаки из AttackFrameCount + AttackHitFrame, а Combat видит только Core+Data. Эти числа выводятся из Attack-клипа и его маркера (ClipMarkers). Это и есть та зависимость, которую фаза 2 плана снимает: тайминг переедет в объявленные доли, а клип останется показом.

◆ WindupShare

float Guildmaster.Data.Definitions.AnimationArchetypeData.WindupShare
get

Доля свинга до контакта (0..1) — ОБЪЯВЛЕННЫЙ тайминг удара, тот самый, по которому сим считает замах.

Клип его больше не диктует: он показ, а число живёт здесь.

Значение замеряется из клипа (кадр контакта / число кадров) редакторной кнопкой и записывается сюда, а не читается каждый раз. Так замер остаётся честным, а рантайм — свободным от AnimationClip: он движковый объект, из-за которого тайминг был недоступен быстрым headless-тестам.
