Detailed Description

Одно событие боя со штампом тика.

Показ отдаёт события, когда доходит до их тика; режиссура (подводки, slowmo «чуть раньше») читает те, до которых показ ещё не дошёл — в этом весь смысл лага: то, что было бы предикцией, становится знанием.

Почему не ссылки на RuntimeUnit: событие приезжает из прошлого, а живой юнит уже в будущем. Поэтому здесь только id и готовые числа, а состояние показ берёт из снимка того же тика.

Как читать поля по виду события:

UnitSpawned / UnitDied / AttackInterruptedSourceId — юнит.
DamageDealtSourceId → TargetId, подробности по PayloadIndex.
HealedSourceId → TargetId, Amount — величина.
AttackEvadedTargetId — тот, кто уклонился.
AttackStartedSourceId → TargetId.
AreaHitгеометрия по PayloadIndex.
BattleEndedисход по PayloadIndex.
BattleResetполей нет.

◆ SubTick

readonly float Guildmaster.Combat.Tape.TapeEvent.SubTick

Доля тика [0..1), внутри которой событие случилось на самом деле.

0 = на границе тика, то есть доли у события нет — так едут все события, у которых нет своего момента внутри шага (смерть, наложение эффекта, периодика).

Это подача, а не правила. В модели событие по-прежнему принадлежит тику Tick целиком: доля считается при ЗАПИСИ из уже известных симуляции чисел и на сам расчёт боя не влияет. Баланс, чек-суммы и зеркальные тесты её не видят.

Зачем: без неё поза и позиция текут по кадрам (доля кадра есть у обоих), а вспышка, цифра урона, звук и hitstop щёлкают на границе тика — разброс до 33 мс мимо кадра контакта, в среднем ~16. Ощущается как вялый удар при идеально посчитанном уроне.
