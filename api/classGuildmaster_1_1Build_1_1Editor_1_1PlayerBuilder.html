Detailed Description

Сборка плеера из командной строки: то, что зовёт локальная выкладка в Steam (scripts/steam-publish.ps1).

Зачем свой метод, если в CI собирает game-ci. Тот генерирует такой же метод сам, внутри докер-образа; локально образа нет, а звать BuildPipeline из PowerShell нельзя. Здесь же живут две вещи, которые иначе разъехались бы между двумя дорогами сборки: список сцен и назначение версии.

Версия приходит аргументом и назначается ЗДЕСЬ, потому что владелец версии релиза — тег, а не ProjectSettings. Правка безопасна: локальная выкладка гоняет теневой проект, у которого ProjectSettings — копия, а не ссылка на репозиторий.

Сцены берутся из Build Settings и только включённые: второй список сцен рядом разошёлся бы с настройками проекта на первой же новой сцене, и заметили бы это по чёрному экрану у игрока.

Почему папка называется Player, а не Build: корневой .gitignore прячет [Bb]uild/ на любом уровне — это правило из шаблона Unity, и оно молча съело бы этот файл вместе с asmdef. Ошибка выглядела бы как «у меня работает, а из репозитория не собирается».
