Detailed Description

Чистая детерминированная арифметика тайминга авто-атаки (вики «14»).

Целочисленная по построению — float участвует только в конверсии AttackSpeed → intervalTicks с явной политикой округления (MidpointRounding.AwayFromZero), чтобы исключить banker's rounding и рассинхрон чек-суммы между сборками/платформами.

Модель «фикс. длительность свинга + кламп»: intervalTicks = max(1, round(TickRate / AttackSpeed)) attackDurationTicks = min(MaxAttackAnimTicks, intervalTicks) windupTicks = clamp((hitFrame * attackDurationTicks) / frameCount, MinWindupTicks, intervalTicks − 1)

Хвост-доигрыш клипа удара после кадра контакта = attackDurationTicks − windupTicks.

Это «задняя половина» анимации свинга: урон уже нанесён (на кадре контакта), но юнит всё ещё доигрывает движение и остаётся «занят» (рут либо штраф скорости). Выводится из той же модели, что и WindupTicks, поэтому автоматически масштабируется со скоростью атаки — в отличие от абсолютных секунд не «расклеивается» при баффах скорости.

Нет реального клипа (frameCount ≤ 0 или hitFrame ≤ 0) → windup был чистым телеграфом (пол SimConstants.MinWindupTicks), доигрывать нечего → 0. Вычитание (а не независимая пропорция «хвостовых кадров») сознательно: оно поглощает округление windup, поэтому windup + доигрыш = attackDurationTicks ровно, без фантомного зазора.

static int Guildmaster.Combat.AttackTiming.RecoveryTicks ( float  seconds)
inlinestatic

Тики замаха до кадра контакта.

Целочисленное деление = floor (детерминированно). Кламп: нижний — SimConstants.MinWindupTicks (телеграф-пол), верхний — intervalTicks − 1 (удар не совпадает с тиком старта следующей атаки). Пустой клип (frameCount ≤ 0) или hitFrame ≤ 0 → нижний кламп.

Дополнительное восстановление (сверх анимационного доигрыша) в тиках из секунд. Детерминированное округление (MidpointRounding.AwayFromZero), как у интервала. ≤ 0 сек → 0 тиков.
