Detailed Description

Авторинг ЗНАЧЕНИЙ контента (баланс) — write-сторона к read-инструментам (SimBench, Content Hub «Balance»).

Сосед ContentCrudService: тот владеет жизненным циклом ассета (create/duplicate/delete + id), этот — правкой полей внутри ассета (статы, кулдауны, поля эффектов). Всё через SerializedObject

  • Undo; каждая правка возвращает Change (было→стало) для аудита. id/схему НЕ трогает. Editor-only, рантайм-SO не мутирует (правка в редакторе = авторинг, не игровая мутация).

Потребитель — агент, а не игровой код. Вызывается из редакторных сессий (Unity MCP execute_code, балансные прогоны, Content Hub), поэтому ноль ссылок из Assets/_Project/Scripts — нормальное состояние, а не мёртвый код. Аудит 2026-07-26 записал его в кандидаты на удаление именно по этому признаку; решение Макса — сервис остаётся, это рабочий инструмент петли баланса.

Найти ЛЮБОЙ ассет-ScriptableObject по имени — путь к конфигам, у которых нет id, потому что они не ContentDefinition (ClassBalanceConfig, StatsConfig).

Заведено под правку классовых коридоров: их числа — такой же предмет балансного вердикта, как сила кита, и они обязаны крутиться тем же пакетом с откатом, а не руками по YAML. Поиск строго по имени ассета: id у конфига нет, а совпадение имён внутри Assets/ исключено правилом «один конфиг — один владелец». Возвращает первое совпадение в стабильном порядке по пути.

Задать значение модификатора стата: заменить ПЕРВЫЙ с этим статом (с любым Op) либо, если такого нет, добавить новый с op .

«Первый» имеет значение, когда модификаторов одного стата в _stats несколько: правка достанется первому, а сложение по ModifierOp может отдать победу другому — например, второму Override. Тогда аудит покажет честную правку, а в игре не изменится ничего. Случай редкий (сегодня таких ассетов нет), но тихим он быть не должен — поэтому о дублях предупреждаем в консоль.

Задать СКАЛЯРНОЕ поле по пути SerializedProperty — float, int, bool или enum (_movingAttackSpeedPenaltyPct, _castConditionCount, _consumesTriggerTag, _ai._autoAttackTargeting).

Значение всегда приходит числом, потому что Change ведёт аудит в float и обязан уметь записать «было → стало» для любого поля одинаково. Для bool ненулевое значение = true; для enum число — это его сериализованное значение (флаговые enum складываются, как в ассете).

Почему не только float: балансная правка кита регулярно упирается в переключатель, а не в число — «расходует ли способность теги», «сколько целей нужно для каста», «кого бьёт авто-атака». Без них пакет применялся бы наполовину, а вторая половина уезжала бы в ручную правку YAML мимо Undo и аудита.
