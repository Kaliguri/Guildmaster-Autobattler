Detailed Description

Эффективные статы юнита — один путь для боя и для всех инструментов, которые показывают числа.

Порядок каскада здесь ровно тот же, что делает RuntimeUnitFactory.Create: дефолты конфига → классовая база → скейлеры вида/подвида врага → модификаторы персоны (SO). Не включает статы от пассивных GrantedEffects: те живут в EffectSystem и появляются уже в бою.

Собран как единственный владелец после аудита 2026-07-26 (R1-48/R1-72/R1-74, T-10): каскад был переписан в трёх местах, и балансный аудитор — тот, по чьим таблицам принимаются решения — пропускал классовый слой и слой вида, то есть показывал MaxHP и MoveSpeed, которых в игре не бывает.

Тот же каскад плюс два слоя, которые есть у собранного игроком кита: Судьба сосуда и статовые моды надетых предметов (включая баннеры команды).

Порядок групп значим и повторяет боевую сборку: класс и вид ложатся первыми, затем персона, затем Судьба, затем предметы. Перестановка меняет результат — Override побеждает последний, а PercentMult множит уже накопленное.
