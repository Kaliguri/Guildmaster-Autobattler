Кооперативный автобатлер-рогалик в реальном времени (с паузой) на Unity 6000.4.8f1, C#, Windows/PC.
Этот файл читается Claude Code и Cursor AI автоматически. `AGENTS.md` в корне — указатель сюда же
(для Codex); содержимое живёт только здесь.

**Что здесь есть и чего нет.** Здесь — правила и ловушки, которых не видно из файлов. Инвентарь

## Правила слоёв

Всё, что ниже, — про то, как к подсистеме обращаться. Обход шва считается дефектом, а не срезкой.

| Слой | Правило |
|---|---|
| DI | **VContainer**, никаких синглтонов: зависимости только инъекцией. |
| События | **MessagePipe** pub/sub через VContainer — развязка Combat → UI / Audio / VFX. |
| Асинхронность | **UniTask** вместо корутин для всего time-based. |
| Звук | Только за `IAudioService`. FMOD API из игровой логики не дёргать. |
| Ввод | Только за `IInputService` (`Guildmaster.Core.Input`): карты действий строятся в коде, контексты по фазе игры. Почему в коде, а не ассетом, и какова цена — запись [«Input Maps Are Built In Code»](docs/wiki/tech/00-meta/journal/2026-07-30-input-maps-are-built-in-code.md). |
| Камера | **Cinemachine**, 4 режима (`Action` / `Overview` / `Dev` / `Map`), `CameraModeController`. Боевые режимы клампятся зоной арены, `Map` — своей. |
| Текст | Локализация EN + RU: ключи закладываются в SO сразу, не «потом». |
| Твины | **LitMotion**, но пока живёт точечно (`Presentation/UnitView.cs`) — UI-анимации и боевые цифры на него ещё не переведены. |

## Ловушки стека

То, на чём агенты уже спотыкались и споткнутся снова.

- **Easy Save 3 и Feel удалены 31.07.2026, пакет `com.unity.visualscripting` — вместе с ES3.** Ни
  один из троих не вызывался из кода, сцен и префабов, а платили за них каждым domain reload. Если
  вернёшь ES3 — вернётся и требование к пакету, и придётся заново дописать
  `Unity.VisualScripting.*` в `references` у `FMODUnityEditor.asmdef` (мы их сняли; сам код FMOD за
  дефайном `UNITY_VISUALSCRIPTING_EXIST` и гаснет сам).
- **Newtonsoft.Json** авто-ссылается на все сборки (`isExplicitlyReferenced: 0`), правка asmdef не
  нужна — **кроме сборок с `overrideReferences: true`** (их у нас включает Odin): там авто-ссылка
  отключена целиком и `Newtonsoft.Json.dll` надо дописать в `precompiledReferences` руками.
  Готча: `Vector2` требует конвертера, иначе сериализатор уходит в рекурсию по `normalized`.
- **Addressables** прямой загрузки по адресу в коде не имеют — живут только как основа Localization.
- **Visual Effect Graph** установлен, но не используется: ни одного `.vfx`. Боевые VFX — свой слой
  (`VfxData` → префаб → пул). **ProBuilder** нужен как зависимость группы `probuilder` в Unity MCP.
- **Shapes** лежит в `Assets/Shapes/`, а не в `Plugins/`. **Odin** подключается в Editor-сборках через
  `overrideReferences` + `precompiledReferences`. **Roslyn** даёт дефайн `USE_ROSLYN` для
  `validate_script`.
- **Steam:** `steam_api64.dll` в `Facepunch.Steamworks/redistributable_bin/win64/`, инициализация —
  `Net/FacepunchTransportBootstrap.cs`. **MPPM** гоняет кооп в редакторе (до 4 виртуальных игроков).

## Сохранения

> Раздел держит правду в одиночку. Доки `10-reference/tech-stack` и `10-reference/saves`, которые
> числили бэкендом Easy Save и `persistentDataPath`, **удалены 30.07.2026** вместе с остальным
> описательным справочником. Правда о сейвах — здесь и в коде.

Живой и единственный сейв — **`JsonFileSaveService`** за интерфейсом `ISaveService`: Newtonsoft,
каталог `Saves/` под корнем `GameDataPath`, атомарная запись через временный файл + `.bak`, битый
файл уезжает в `.corrupt`.

- **Корень — `LocalLow/Alebardium/Guildmaster/`, а НЕ `persistentDataPath`.** Последний растёт из
  `productName`, и переименование игры унесло бы сейвы игроков вместе с маской Steam Cloud. Кодовые
  имена в `GameDataPath` не менять никогда — инвариант держит `GameDataPathTests`.
- **Сохраняем данные, а не объекты:** durable-состояние забега — плоский DTO по строковым id, боевые
  сущности собираются из него фабрикой. Поэтому сильные стороны готовых плагинов вроде Easy Save
  (графы объектов, ссылки на `UnityEngine.Object`, полиморфизм) решают проблему, которой у нас нет —
  за это ES3 из проекта и вынесли.
- **Ключ сейва — это путь** в дереве: `prefs`, `profiles/{id}/profile`,
  `profiles/{id}/guilds/{gid}/run`. Каждый файл — конверт (`schemaVersion` + `gameVersion` +
  `payload`); версия схемы объявляется атрибутом `[SaveSchema]` на DTO, не полем внутри состояния.
  Загрузка возвращает `SaveLoadResult<T>`: `Ok` / `Missing` / `Corrupted` / `TooNew` (сейв из более
  новой версии игры — **не грузим и не затираем**) / `Unsupported`.
- **Steam Auto-Cloud** синхронизирует по маске пути и не знает, кто писал файл. Маска —
  `Saves/**/*.json`, поэтому служебные суффиксы идут ПОСЛЕ расширения (`run.json.bak`).
- **Данные компьютера — отдельное хранилище:** `ILocalSaveService` → `Local/` (вне облачной маски),
  там `machine.json` за `IDisplayService`. Синхронизировать нельзя: чужое разрешение на втором ПК в
  худшем случае даёт чёрный экран. Частоту обновления Unity меняет только в эксклюзивном
  полноэкранном; разрешение Unity сам пишет в реестр Windows до первой сцены — владельцем остаётся
  наш файл, потому что мы применяем поверх.

Полное ТЗ и фазы — [`40-planning/save-system`](docs/wiki/tech/40-planning/save-system.md).

## Где живёт правда

**HARD: у каждого факта один владелец, и владелец выбран по тому, что ломается при расхождении.**

| Владелец | Что держит | Почему не может соврать |
|---|---|---|
| **Код** — `<summary>`, `<remarks>`, `// почему` | всё про один файл: контракт метода, смысл числа, локальная готча | правится в том же диффе |
| **Тест** с говорящим именем | кросс-файловый инвариант и контракт шва | падает при нарушении |
| **`00-meta/journal/`** | почему так решили и что отвергли | append-only, отставать нечему |

Следствия, каждое обязательно:

- **Инвариант, живущий между файлами, идёт в тест, а не в комментарий.** Комментарий виден только
  одной стороне шва — вторая нарушит и не узнает. Прецедент: `GameDataPathTests` держит кодовые
  имена в `GameDataPath`.
- **Док, который ПЕРЕСКАЗЫВАЕТ код, заморожен** — читать как замысел, не как правду; править не
  нужно. Владелец статуса один: `status` во frontmatter самого дока (`archive` = заморожен). Списка
  здесь нет намеренно. Кластер `20-explanation` расформирован, описательная часть `10-reference`
  удалена; живы доки, которые код **предписывают** (`code-standards`, `editor-tools`, палитра,
  типографика, сортировка), генерируемый `audio-inventory` и `30-how-to` про среду.
- **Doxygen публикует API-сайт прямо из `Assets/_Project/Scripts`** — справочник классов
  генерируется, руками его не пишем.

### Журналов тринадцать жанров — список не помним, маршрут знаем

Одного журнала у нас нет и не будет: у решений, реестров, прогонов и заходов разные жанры и разные
владельцы. Полный список **генерируется**, потому что рукописный отстанет от диска за неделю:

```powershell
./scripts/journals.ps1          # карта: жанр, владелец, дата последней записи
./scripts/journals.ps1 -Check   # гейт: журнал без жанра, брошенный заход, дописанный архив
```

| Жанр факта | Дом | Ведёт |
|---|---|---|
| инженерное решение, «почему так» | `wiki/tech/00-meta/journal/` — файл на запись | tech-scribe |
| ГД-решение, принятое Максом | `wiki/gdd/00-meta/journal-adr.md` | gdd-scribe |
| отложенный техдолг | `wiki/tech/00-meta/tech-debt.md` | tech-scribe |
| проблема баланса, замер, кит | `docs/balance-issues.md` | balance |
| прогон Suno: seed, дельта, вердикт | `docs/ost-run-log.md` | music |
| развилка без вердикта · закрытая развилка | `wiki/gdd/00-meta/open-forks.md` · `closed-forks.md` | gdd-scribe |
| чем код расходится с замыслом | `implementation-status.md` в relics · enemies · items · effects | gdd-scribe |
| идея без вердикта · отложенное по подсистеме | `relics/draft-ideas.md` · `backlog-*.md` | gdd-scribe, gamefeel-vfx |
| личный инбокс Макса — **агент не пишет** | `wiki/gdd/00-meta/open.md`, разборы в `00-meta/inbox/` | — |
| ход мысли по живому заходу | `docs/<фича>-progress.md`, временный | ведущий заход |

Жанр решает, что в файл писать; путь без жанра — приглашение свалить факт куда попало. Новый
журналоподобный файл обязан получить жанр в `journals.ps1`, иначе гейт красный: это дешевле, чем
через месяц искать, в каком из ста сорока файлов лежит нужное.

### Запись в журнал — по коммиту, а не «по фиче»

После коммита, тронувшего `Assets/_Project`, ответь на три вопроса. **Любое «да» — пишем запись:**
была развилка (выбрали одно из двух и более)? потратили время на неочевидное? заложили инвариант,
который легко нарушить снаружи? Ни одного «да» — не пишем, git и так помнит.

Запись — **новый файл** `docs/wiki/tech/00-meta/journal/ГГГГ-ММ-ДД-slug.md` (slug латиницей: он
попадёт в коммиты и комментарии кода как стабильный id). Существующие файлы не читаются и не
правятся. Шаблон целиком:

```markdown
---
title: "Journal - Name In English"
date: 2026-07-30
tags: [combat, tick]
---

**Решили:** что именно приняли, одной фразой.
**Почему:** причина + какую альтернативу отвергли и чем она хуже.
**Сказано:** «формулировка Макса дословно» (дата, сессия 8 симв). Решение пришло от него —
строка обязательна; решение чисто инженерное — опустить.
**Грабли:** на что потратили время зря; чего не видно из кода. (Нет — строку опустить.)
**Владелец правды:** `File.cs`, тест `SomeInvariantTests`.
```

Строка «сказано» существует потому, что пересказ невидим: между словами Макса и записью стоит
агентская формулировка, и расхождение всплывает месяцем позже уже как «правда». Слова не
причёсываются — опечатки и пунктуация остаются, сокращение только многоточием, середина фразы
молча не выбрасывается. Берётся из архива диалогов (`Transcripts.ps1 quote`), не из своего
резюме: резюме — уже пересказ.

Строка «владелец правды» обязательна: она сшивает журнал с кодом. Без неё журнал через месяц снова
начнёт пересказывать код.

### ГДД — своё правило: журнал на решение, карточка на дифф

**HARD (принято 2026-07-30).** С дизайн-документацией нельзя как с tech-справочником: там правду забрал
код, поэтому справочник заморозили. В ГДД **карточка держит замысел**, код держит реализацию, а
расхождение между ними — третий факт со своим домом. Поэтому ГДД не замораживается, но и «сверить с
кодом» для него не значит «переписать по коду».

**1. Журнал ГД пишется на решение, а не на коммит.** Макс сказал «ок» по дизайну → запись в
`docs/wiki/gdd/00-meta/journal-adr.md` в тот же ход, до реализации. Коммит тут не якорь: решение
рождается в чате и до кода может не дойти неделю.

**2. Дифф по контенту и механике обязывает проверить ГДД.** Тронул
`ScriptableObjects/{Relics,Enemies,Items,Effects}`, `Scripts/Combat` или контентные ассеты — один вопрос:
**описанное в карточке или главе теперь врёт?** Врёт — либо правишь карточку (если прав код), либо
заводишь расхождение в `implementation-status`. Не врёт — не пишем ничего.

**3. Карточка контента несёт только механику — что и как работает.** Маршрут для остального:

| Факт | Дом |
|---|---|
| почему выбрали так, что отвергли | `00-meta/journal-adr.md` |
| что не реализовано, чем код расходится с замыслом | `relics/implementation-status.md`, `enemies/implementation-status.md` |
| неутверждённые числа и имена, `proposed`, незаданные поля | `00-meta/open-forks.md` §2.5 |
| что и как замерить, где кит сломает баланс | `docs/balance-issues.md` |
| идея без вердикта | `relics/draft-ideas.md` |

**4. `00-meta/open.md` — личный инбокс Макса, а не рабочий док.** Он пишет туда черновые мысли как
думает; агент **не пишет туда ничего**. Разбирая инбокс: оригинал целиком и **слово в слово** копируется
в `00-meta/inbox/ГГГГ-ММ-ДД.md` (свой файл на каждый прогон, плюс таблица «куда что уехало»), содержимое
разносится по домам, а сам `open.md` **чистится до пустого**. Переписывать заметку «как надо» нельзя
нигде: формулировка автора — сам по себе факт.

Число пишется как число, без оговорок о происхождении. Полное правило и образец футера карточки —
`relics/template-relic-card.md` §HARD; процедура — правило 5 скилла `xgaida-x-nixi-gdd-scribe`.

## Правку `.cs` проверяет скрипт, а не редактор

**HARD: тронул `.cs` — гони `./scripts/compile-check.ps1`, не проси рефреш у Unity.** Скрипт отвечает
«компилируется ли» за 1.7–3 секунды на сборку (все двадцать две — 44), потому что собирает Roslyn'ом из
установки редактора по готовым командам Unity из `Library/Bee/artifacts/*.dag/*.rsp`; список исходников
берёт с диска, так что новые файлы тоже видит. Без аргументов проверяются сборки, задетые правками;
`-All` — все; `-Meta` — заодно завести `.meta` новым скриптам.

Почему это правило, а не удобство: перезагрузка домена стоит от 10 до 56 секунд и **дорожает по ходу
сессии** (замер 2026-07-31: первая 1 с, 278-я — 56 с, 108 минут ожидания за сессию). Компиляция в чужом
редакторе — это и отнятое время Макса, и замороженный ошибкой сборки тулинг. Диагностика самой кривой —
`editor-health.ps1`; лечится она рестартом редактора, а не чисткой проекта (на свежем редакторе домен
грузится за секунду).

Редактор всё ещё нужен для того, что без него не делается: импорт и создание ассетов, префабы, сцены,
анимации, UI-превью. Тесты идут мимо него — `run-tests.ps1 -Where Shadow`.

## Тесты: узко локально, целиком — в CI

**HARD: полный прогон после каждой правки НЕ гоняем.** Он идёт минуты, требует единственного на все
сессии теневого проекта и потому ставит соседей в очередь. Лестница такая:

| Когда | Что гонишь | Цена |
|---|---|---|
| тронул `.cs` | `./scripts/compile-check.ps1` | 2–7 сек |
| дописал кусок логики | `run-tests.ps1 -Where Shadow -Filter <класс или неймспейс>` | 30–60 сек |
| сдаёшь блок целиком | полный EditMode, **один раз** | минуты |
| pull request | полный EditMode + PlayMode + сборка | делает CI, не твоё время |

**Прогон видит ВСЁ рабочее дерево, а не только твои правки.** `Assets` в теневом проекте — junction на
живой репозиторий (так задумано: балансный стенд читает свежие SO). Отсюда два следствия, которые надо
держать в голове: зелёный прогон означает «дерево сейчас зелёное», а не «мой код зелёный», а красный
может быть чужим — скрипт печатает, сколько файлов в дереве изменено, чтобы это читалось сразу.

**Теневой проект один на всех.** Второй Unity в ту же `Library` не стартует, поэтому `run-tests.ps1`
**ждёт освобождения** (до 20 минут, `-WaitMinutes 0` — не ждать). Раньше это выглядело как «прогон не
состоялся» и читалось как поломка тестов.

## А ассеты — ровно наоборот

**HARD: пока редактор открыт, ассеты правим ТОЛЬКО через него.** `.asset`, `.prefab`, `.unity`,
`.anim`, `.controller` — через MCP (`execute_code`, `manage_*`) или руками в инспекторе. Правка YAML на
диске при живом редакторе **теряется**: Unity держит объект в памяти и при следующем сохранении
перезаписывает файл своей версией. С выключенным Auto Refresh он вдобавок не перечитывает диск сам,
поэтому правка не подхватится даже до перезаписи — выглядит так, будто её не было.

Мимо редактора ассеты можно править **только при закрытом Unity** (`statdb.ps1` и подобное; открыт ли
он — покажет `Temp/UnityLockfile`). Результат любой правки сверяется **на диске** (`git diff`), а не по
ответу инструмента: domain reload откатывает несохранённое.

Правило симметрично предыдущему и легко путается, поэтому одной строкой: **код — файлами мимо
редактора, ассеты — через редактор.**

## CI/CD

`ci.yml`: `changes` (paths-filter) → `test` (`unity-test-runner`, editmode + playmode) + `build`
(`unity-builder`, StandaloneWindows64) → `ci-gate`. Секреты: `UNITY_LICENSE`, `UNITY_EMAIL`,
`UNITY_PASSWORD`.

Сборка гоняется **только на pull request и на master** — она дороже тестов, а push в dev ими и так
закрыт. Артефакт не публикуется: job отвечает на вопрос «собирается ли». Плеер собирается на
**Linux**-раннере, потому что Standalone у нас на Mono (IL2CPP в `ProjectSettings` задан только для
Android) — переезд Standalone на IL2CPP потребует windows-раннера.

Документацию обслуживают `docs-lint.yml` (блокирует PR при битых ссылках в vault) и `docs.yml`
(публикация сайта).

```powershell
./scripts/run-tests.ps1
```
