## Раунд 2 (2026-07-25) — 10 находок

### 1. Видео-вставка слишком большая; спейс до табов; иконки +50%; статблок «поплыл» — СДЕЛАНО (ждёт play-QA)

Иконки малого чипа 16→24. Статблок переделан (см. п.2) — нечётность больше не видна.

### 2. Порядок блоков правой панели + подписи статов без сокращений — СДЕЛАНО (ждёт play-QA)
Порядок: имя → теги → видео → способности (без заголовка) → характеристики → улучшения → нарратив.
Нарратив внизу с резервом 4 строки (min-height 92), чтобы низ панели не дышал за текстом.
Статблок: строки «подпись — значение» в две колонки, подписи полные («Магическая броня»).

### 3. Отступы тулбара не совпадают с краями грида — СДЕЛАНО (ждёт play-QA)
Причина: всегда видимый скроллбар грида ужимает содержимое на свою ширину, а тулбар о нём не знал.
Заведён токен `--gm-scrollbar-width`, правое поле тулбара = зазор + ширина скроллбара.

### 4. Теги потеряли hover/нажатие — СДЕЛАНО (ждёт play-QA)
`pickingMode` тег-чипа вернулся в `Position` — отклик как у табов.

### 5. Табы (категории инвентаря и верхняя лента) — зоны и границы — СДЕЛАНО (ждёт play-QA)
Полоса категорий без padding, высота 52, табы равными долями на всю высоту + вертикальные
разделители. Лента режимов: табы на всю высоту ленты, стык без зазора, разделители, крайние
(`--first`/`--last`) забирают поле скошенного торца.
**Готча:** UITK НЕ поддерживает `:first-child`/`:last-child` (в консоли «Unknown pseudo class»,
правило молча не применяется) — крайность помечается классом в разметке.

### 6. Таб настроек не выглядит нажатым, пока открыто ESC-меню — СДЕЛАНО (ждёт play-QA)
`MenuRouter.IsSystemMenuOpen` + `RunModeBarView.SetMenuActive`; настройки держат своё состояние
отдельно от радио-набора режимов, чтобы открытое меню не сбивало подсветку текущего режима.

### 7. Двойное затемнение фона — СДЕЛАНО (ждёт play-QA)
`UiNavigator.SyncVisibility` оставляет скрим только самому нижнему видимому Modal, остальные
получают `gm-screen--scrimless`. Сколько бы модалок ни легло стопкой — затемнение одно.

### 8. Второй стиль кнопки выглядит плохо — СДЕЛАНО (ждёт play-QA)
Речь про secondary-кнопки главного/ESC-меню («Продолжить», «Настройки», «Выход»). Плоская плашка
читалась выключенной рядом с латунной primary. Добавлены латунная «подставка» снизу, разгорающийся
контур и латунная подпись на наведении; нажатие вдавливает (подставка гаснет, фон уходит в sunken).

### 9. Возврат в главное меню не убирает верхнюю панель и «Начать» — СДЕЛАНО (ждёт play-QA)
Причина: топбар показывался по одному лишь «есть RunState», а в главном меню забег ещё жив (сейв
не сбрасывается). Условие видимости дополнено `&& !_mainMenuOpen`; battle-center уходит вместе с ним.

### 10. Кнопка «Начать» — центровка, отступ, иконка — СДЕЛАНО (ждёт play-QA)

### 1. Наведение на крайние табы снова выходит за скошенный угол — ОТКРЫТ

### 5. Кнопка залипает в нажатом виде — ИЗУЧЕН, ЖДЁТ ПРОВЕРКИ МАКСА (решение: дальше не копаем)

**Это известный баг САМОГО UI Toolkit, а не наш код.** Репорты с 2022, Unity в январе 2024:
issues «в grab bag», ETA нет. Три воспроизводимых триггера по обсуждениям, и ДВА есть у нас:
- `transition-duration` на состояниях — кнопка застревает в подсвеченном виде.
  У нас стоял на `.gm-chip` (`background-color`, 0.12s) → **снят**, ждём проверки в билде;
- uGUI `EventSystem` рядом с UI Toolkit — у нас `EventSystem` + `InputSystemUIInputModule`
  в `CoreScene`. Трогать НЕ будем: он нужен Input System, лечение хуже болезни;
- скрытие/показ панели, когда курсор не над UI (наш случай с ESC-меню и роутером).

**Починить «правильно» из кода нельзя:** `pseudoStates` в UITK помечены internal, публичного API
сброса `:hover`/`:active` нет. Единственное надёжное лечение — не вешать подсветку на псевдоклассы,
а держать собственный класс состояния во всех интерактивных компонентах. Решение Макса: **ради
некритичного бага это не делаем**. Если снятие transition не помогло — находка закрывается как
баг движка и ждёт фикса Unity.

Симуляцией (UI Test Framework) баг НЕ воспроизводится ни на `Button`, ни за пределами панели —
что сходится с диагнозом «живёт в связке реальный ввод + EventSystem». Тесты состояний удалены,
чтобы не создавать ложной уверенности «состояния покрыты».

## Цветовой ресёрч UI — ПЕРВЫМ ДЕЛОМ (заведён 2026-07-25)

Повод: синяя рамка фокуса. Дело не только в том, что она из чужой темы — вопрос шире: **какой
палитрой мы вообще имеем право говорить в интерфейсе**. Сейчас у нас четыре рампы (ink / brass /
parchment / danger), и в них НЕТ ни одного холодного тона. Любое состояние, которому нужен «не
латунный» акцент (фокус, выделение, информационная подсветка, «сейчас выбрано» против «наведено»),
упирается либо в оттенок латуни, либо в чужой синий.

### РЕШЕНИЕ МАКСА 2026-07-25: «тёплый свет», а НЕ монохром

Текущий монохром был **временной времянкой**, а не выбранной эстетикой — и он доехал до предела
(три разные роли делят один `ink-300`, см. провалы ниже). Правило, которое принимаем вместо него:

> UI **по ощущению** остаётся тёплым — но цвета в нём могут быть любыми, в том числе яркими.

Разворачивается в три рабочих ограничения:

1. **Каркас неприкосновенно тёплый.** Фоны, поверхности, текст, рамки — только ink / brass /
   parchment. Ощущение задаёт каркас, и холод в него не пускается.
2. **Акценты — любого цвета, но через тёплый фильтр.** Чистого RGB не бывает: зелёный уходит в
   мховый, синий — в грозово-серый с янтарным подмесом, фиолетовый — в винный. Тени всех рамп
   тёплые. Ограничение на тон и насыщенность, а не на набор цветов.
3. **Насыщенность — привилегия.** Ярким имеет право быть то, что кричит по делу (опасность,
   редкая находка, критическое состояние). Остальное живёт приглушённо, иначе тёплый свет
   забивается и правило 1 перестаёт читаться.

**Охват (решение Макса):** сейчас — только UI. Боевая палитра идёт СЛЕДОМ отдельным треком (ниже).

### Результаты аудита (проведён 2026-07-25)

**Хорошее: ярусы токенов не протекают.** Во всех `.uss` нет ни одного цветового литерала мимо
токенов — только `rgba(0,0,0,0)` там, где фон рисует Painter2D. Дисциплина яруса держится.

**Находка A. Витрина палитры ВРЁТ.** Образцы цветов в `UiGalleryScreen.uxml` вписаны инлайновыми
числами (`background-color: rgb(217, 178, 106)`). Единственный экран, по которому мы будем
принимать новую палитру, не изменится при смене токенов. **Чинится первым** — иначе ресёрч слепой.

**Находка B. Палитр не одна, а ДВЕ, и вторая вне контроля.** UI тёплый и токенизированный, а
боевой слой держит свою, захардкоженную в C#: команды `(0.2,0.5,1)` против `(1,0.3,0.2)`, хил

## Ревизия вёрстки UITK — отдельный трек (заведён 2026-07-25 по решению Макса)

Не находка QA, а разговор о фундаменте: код UI-слоя (MVVM, навигатор, токены, компоненты) собран
хорошо, а **вёрстка держится на числах вместо отношений**. Каждый размер — договор, который живёт
в комментарии, а не в механике: поменял ширину панели — руками пересчитывай высоту вставки.

**ЗАКРЫТО 2026-07-25 (`6517397a`) — п.7, выравнивание тулбара с гридом.** Корней оказалось три:
1. `642` было ПРОСТО НЕВЕРНЫМ числом: правильная сумма — 638 (32 + 4×(132+16) + 14). Три захода
   подпорками лечили симптом верной по смыслу конструкции с ошибкой в арифметике.
2. **USS не поддерживает `calc()` вообще** — ни в каком виде, фичу просят с 2021 года
   (`docs.unity3d.com/Manual/UIE-USS-CustomProperties.html`; там же: `var()` нельзя внутри других
   функций, математики над переменными нет). В файле уже жил `calc(var(--gm-space-0) * -1)` у рядов
   слотов и МОЛЧА не работал. Вывод для трека: «размеры формулой из токенов» в USS невозможны —
   либо одно число + тест-инвариант, либо контрол на C# (как `AspectBox`).
   Два отступа тулбара справа теперь складывает раскладка: `margin` + `padding`, флекс суммирует сам.
3. Поле поиска не гасило собственный `margin` темы Unity (4px) — левый край стоял правее карты.

Проверено измерением: `search.left == card0.left` (Δ=0), `sort.right == card3.right` (Δ=0).

**Отладочная готча, стоившая получаса** (в память тоже): правка `.uss` при живой панели даёт не
старый стиль, а КАШУ — у карточки `border-width` стал 132, туда уехало значение `width`. Панель
держит старую распарсенную таблицу и тянет значения из новой. Все замеры в этот момент врут.
Лечение: `ImportAsset(папка темы, ImportRecursive|ForceUpdate)` + `RequestScriptReload()`.

**Симптомы, которые уже стоили раундов QA:**
- ~~`642` (ширина центра)~~ — исправлено, см. выше.
- `320×180`, `205`, `250` — высота видео-вставки, пересчитанная вручную под ширину панели.
- `72` (три строки тегов), `92`/`70` (резерв строк нарратива) — «столько-то строк» в пикселях.
- `--gm-scrollbar-width` — токен, придуманный, чтобы подпереть выравнивание, а не описать вещь.

**Куда копать (мой разбор, обсуждаем):**
1. **Выравнивание — родством, а не симметричными полями.** Элементы, которые обязаны совпадать
   краями (тулбар и грид карт), должны быть детьми ОДНОГО контейнера, задающего ширину. Тогда
   «само считается» по построению, и п.7 не может воспроизвестись в принципе.
2. **Дырки UITK закрывать крошечными контролами, а не числами.** `aspect-ratio` в UITK нет —
   значит нужен `AspectBox`. **СДЕЛАНО 2026-07-25 (`091a2068`)**: `Assets/_Project/Scripts/UI/
   Components/AspectBox.cs`, атрибут `Aspect="16:9"` словами; видео-вставка инвентаря переведена,
   `height` из USS убрана. Проверено: 320 → 180, 420 → 237. Два готчи, стоившие отладки:
   `flex-shrink` по умолчанию 1 (родитель ужимал блок, пропорция терялась) — контрол выставляет 0
   сам; заданному числу UITK оставляет `StyleKeyword.Undefined`, по нему и проверяется «значение
   задано». ОСТАЛОСЬ по этому пункту: такой же контрол для «резерв под N строк текста».
3. **Размеры — в токены.** Ширина панели деталей, размер таро-карты, размер слота сейчас литералы
   в `components.uss`. Токен делает изменение одноточечным (высота топбара уже так живёт).
4. **Витрина должна ловить это раньше Макса.** ЧАСТИЧНО СДЕЛАНО (`a4a3c25f`): витрина переведена
   на ScrollView, ряды перестали растягивать компоненты, палитра честная. ОСТАЛОСЬ: добавить
   состояния (hover / active / disabled / focus), которых в стенде нет вовсе, и разобраться с
   `ToggleRow` без подписей. Отдельно: витрин ДВЕ — сцена `Scenes/UiGallery.unity` (этот UXML) и
   editor-окно `Alebardium/UI Preview` (собирается кодом в `UiPreviewCatalog.BuildGallery`).
   Расходятся; свести к одной.
5. **Тесты-инварианты раскладки** (`com.unity.ui.test-framework`, PanelSimulator): «левый край
   поиска == левый край первой карты», «панель не выше экрана», «видео 16:9». Регрессия ловится
   прогоном, а не глазами в билде.

**Риск, который держим в уме:** сплошной перевод экранов на flex — это пересборка, а пересборка
даёт регрессии (лента режимов в раунде 3 — ровно такой случай). Поэтому не переписывать всё разом:
сначала контейнеры-владельцы выравнивания там, где болит, потом контролы под дырки, потом тесты.

**Критерий приёмки этого трека (формулировка Макса):** визуал и вёрстка должны собираться
УДОБНО И ПОНЯТНО. Проверка простая — «сделай панель шире» или «поменяй местами два блока» обязано
быть правкой в одном месте, без пересчёта чисел в соседних правилах и без чтения комментариев,
объясняющих, откуда взялось `205`. Пока такая правка тянет за собой арифметику — трек не закрыт.
