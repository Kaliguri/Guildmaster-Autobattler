# Заход: кооп на одни рельсы

Временный журнал захода (леса). Сносится по закрытии.

**Заказ Макса 08.08.2026:** после прогона вдвоём — «надо создать норм систему, СТРУКТУРУ или
что-то еще чтобы в принципе таких различий быть не могло, посадить все на ОДНИ рельсы».

## Корень

Канал `SessionRoster` рассинхронизирован по формату в обе стороны: хост пишет шесть полей на
участника, гость читает пять; гость представляется тремя, хост читает четыре. Обе половины глотают
`InvalidOperationException` и молча выходят. Итог — у гостя состав пуст всегда, у хоста
представление гостя не применяется никогда. Регрессия коммита `cf7663512`.

Разъехалось потому, что у канала **нет кодека**: писатель живёт в файле хоста, читатель — в файле
гостя. У шести каналов из тринадцати кодек есть (`ActivityStateCodec`, `SessionStageCodec`,
`RunCommandCodec`, `RunSnapshotCodec`, `PresenceCodec`, `DeploymentIntentCodec`), и ни один из них
не сломался.

3. **Гостевая половина кампании** — экипировка по проводу, «Продолжить»/«К строю», шаг узла.
   Плюс: «Начать» нигде не прямой старт, только голос (уточнение Макса: голосуют ВСЕ, включая
   хозяина; собранное согласие исполняет хозяин).
4. **Стенд** — настоящий гость в тестах, кооп-PlayMode на PR в dev.
5. **Хвосты** — витрина награды (`inventoryFull` зашит в false у гостя), пинг у ника, задержка
   постановки.

## Ход фазы 3

**Проверено и снято с плана:** «Начать» уже везде только голос — и у хозяина
(`DeploymentController.TryStartFromButton` → `ToggleLocal`), и у гостя
(`GuestActivityFollower.ApplyReady` → `BindStart(ToggleLocal)`). Гипотеза о втором пути старта у
гостя, выведенная из строк лога `RequestStart`, при чтении кода **не подтвердилась**: это путь ДО
голоса. Требование Макса «все шлют голос, бой при N из N» выполнено по построению.

- [x] экипировка реликвии у гостя едет по сети — канал намерения расстановки получил тег вида
      (перемещение / надеть), реликвия едет строковым id, хозяин собирает её из своего реестра
- [x] **общий шов экранов узла (каркас)**: `ISessionStageView` + `SessionStageScreens` — показ живёт у обеих
      ролей, роль решает только КТО ОБЪЯВЛЯЕТ. Передышка переехала на него первой; кнопки шлют
      `GoToModeRequest`, который обрабатывает тот же код, что и табы верхней панели.
- [x] **витрина награды переехала на общий шов.** Путь к ней теперь один: `RewardPresenter`

- [x] **шаг узла несёт коробку на каждый вид** (решение Макса 08.08: «своя коробка на экран»).

- [x] **конец узла оказался ХВОСТОМ, а не экраном.** Кнопки «дальше» ложатся поверх того, что уже

## Разведка: где роли расходятся ПО ВОЗМОЖНОСТЯМ

HARD-правило записано в `CLAUDE.md`. Граница по Максу: делится **кто исполняет** (сетевое), а не
**что игроку можно** (геймплейное).

Законно (исполнитель один): петля акта, durable-состояние и сейв, подсчёт согласия, ведение состава,
раздача присутствия, симуляция боя.

Дефекты — восемь экранов узла публикует хозяйская петля (`_role == Owner`), и гость видел из них
один. Полный список в этом файле выше по пунктам.
