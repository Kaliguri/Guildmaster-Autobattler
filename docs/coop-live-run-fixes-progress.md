## Что нашёл Макс на прогоне вдвоём

1. Второй игрок в кампании **не может двигать своих** бойцов, зато **двигает врагов**.
2. В Ристалище гость **не подключается вовсе**, без единой ошибки на экране.
3. У хоста с большой задержкой «игрок отключился», **при том что о подключении не сообщалось**.
4. Кнопка «Продолжить» (общее согласие) **у клиента не появляется**.
5. Reward и прочие «одновременные» экраны — **проверены ли вообще?**
6. Логи МП **не нашлись**: на F2 нет ни кнопки, ни переключателя.

## Корень симптома 1 — один факт отвечал на два вопроса

`OwnUnitsOnly` значил «чужую сторону не трогать», а `ActivitySideAssignment` выводил из него
число сторон. Кампания получила флаг 05.08 → сторон стало две → `TeamFor(seat) = seat % 2` →
у гостя «своя» сторона это враги, и оба слоя проверки прав послушно перевернулись.

**Модель без вывода:** у второй стороны арены есть ВЛАДЕЛЕЦ.

| Мероприятие | Владелец второй стороны | Следствие |
|---|---|---|
| Кампания | энкаунтер | игроки все на первой стороне, вторая не их |
| PvP | другой игрок | участники раскладываются по сторонам |
| Ристалище | никто (ничья) | все на первой, ничью двигает любой |

Право читается одной фразой — **«сторона моя или ничья»** — и живёт в одном месте
(`ActivitySetup.MayCommandSide`), а не двумя копиями в расстановке и контроллере.
Раскладка по сторонам включается ровно там, где вторая сторона принадлежит игроку.

Будущий выбор команды в PvP (заявка Макса 07.08.2026) модель держит: сторона участника —
назначение в составе сеанса, лобби станет его источником вместо порядка входа.

## Фазы

### Фаза 1 — владелец стороны вместо `OwnUnitsOnly` (симптом 1) — СДЕЛАНО, `e6edf494a`

- [x] `OpposingSide` + `ActivitySetup.Opposition`, параметр ОБЯЗАТЕЛЬНЫЙ (умолчание и было миной)
- [x] `MayCommandSide` — единственный владелец правила; `DeploymentInteraction` и
      `DeploymentController` зовут его, а не пишут своё
- [x] `ISessionRoster.AssignSides(int)` → `SplitBetweenSides(bool)`: заказ вместо числа
- [x] `HostSessionRoster.TeamFor` — без деления ВСЕ на стороне хоста (вторая мина: дев-ручка
      `LocalPlayerTeam` разводила хоста и гостя по разным сторонам)
- [x] `ActivityState` + кодек: по проводу едет владелец, а не буль
- [x] тесты: право и раскладка на все три мероприятия, роундтрип состояния, отказ на неизвестном
      владельце. Узкий прогон EditMode — 25/25.

### Фаза 2 — «Продолжить» у гостя (симптом 4) — СДЕЛАНО, `224a22b38`

- [x] гость взводит `battle.continue` и сам показывает экран исхода на площадке
- [x] исход берётся из ЛЕНТЫ (`BattleEndedEvent`), а не пересчитывается по арене
- [ ] **проверить вдвоём вживую** — тестом это не закрыто: экран живёт в UI-роутере
- [ ] PlayMode-тест «согласие гостя на возврат доезжает» — к следующему заходу

Награда кампании сюда НЕ входит — это канал показа, фаза 5.

### Найдено по дороге, НЕ чинено

- У гостя `GameFlow._activityCts` не взводится вовсе (его ставят `RunActAsync` и
  `ShowProvingGroundsAsync`, а гостевой цикл — `PlayAsGuestAsync` — нет). Значит **«В главное меню»
  из системного меню у гостя молча не работает**. Поэтому кнопка «В меню» на экране исхода уходит
  через `ICoopSessionControl.Leave`. Чинить отдельно: у гостя выход = покинуть чужую сессию.

### Фаза 4 — Ристалище (симптом 2)

Ждёт лога с двух машин (`diag net on`). Подозреваемые: лобби не поднято на этом входе,
гость виснет на площадке без состава (`ToSetup()` отдаёт `Roster: null`), ответ «где мы» не доходит.
