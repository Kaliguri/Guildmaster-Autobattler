# Пересборка огня The Pyre — журнал захода

**Ветка:** `feature/unit-tag-icons` (работа идёт поверх балансного захода 2026-07-26).
**Канон:** решение [журнала ADR](wiki/gdd/00-meta/journal-adr.md) «2026-07-26 (ночь, 9)»,
числа — [the-pyre.md](wiki/gdd/relics/the-pyre.md) шаги 4-5 и [burn.md](wiki/gdd/20-combat/effects/burn.md).

## Что собираем

| Механика | Число |
|---|---|
| Поджог | 30 урона/сек, 5 с, обновляется, не стакается, школа Магическая + Огонь |
| «Угли» | +1 стак за любой урон огнём (включая тики поджога), **без потолка**, +1% урона огнём за стак |
| Сход «Углей» | 5 с без подпитки → первый стак через 1 с, интервал ×0.75, минимум 0.25 с |
| Автоатака по горящей цели | расщепляется: 50% Режущий + 50% Огонь (суммарный урон тот же) |
| Воспламенение | 15 урона Огнём за стак, по текущей цели автоатаки, стаки сбрасывает |
| Мана | запас 100, стоимость 60, набор **8 за попадание** автоатаки, потолок **10/сек**, **КД нет** |
| Разгон темпа | +5% скорости атаки за удар до +100% (канон, не режем) |

## Швы в ядре, которых не было

Три из четырёх нужны не киту, а уже записанному канону — кладём как систему, не как костыль.

- [x] **A. Тип урона в боевом событии.** `DamageRequest.Element` + `CombatEventData.School/Element`
      (+ `IsFire`), эхо в `DamageResult.Element` (пригодится искрам по стихии). Реактив теперь
      отличает огонь от стали.
- [x] **B. Множитель урона в pre-damage.** `PreDamageResult.DamageMultiplier` + `AddMultiplier`
      (уязвимости копятся, а не перетирают друг друга); применяется в `CombatSimulation.DealDamageCore`
      ДО брони — это свойство цели, не пробивание источника. Тем же швом ляжет «+25% урона молнии
      по `Мокрой` цели» из combo-rules.
- [x] **C. Клемп набора ресурса.** `UnitData.MaxResourceGainPerSecond` + скользящее секундное окно на
      `RuntimeUnit`; мана по-прежнему капает только с попаданий.
- [x] **D. Расщепление удара по школам.** `IAttackSplitComponent` + `AttackSplit`, резолв в
      `EffectSystem.TryResolveAttackSplit`, применение в `CombatSimulation.DealDamage` (а не в
      AutoAttackSystem — так одинаково работает для мили, линии и снаряда).

## Сборка кита

- [x] «Угли» — `EmberComponent` (множитель огня, кривая схода на `RuntimeEffect.TimerTick`) + ассет
      `Ember.asset` (бессрочный, Stack, тег `Ember`, loc-ключи заведены)
- [x] Правило «урон огнём кладёт стак» — `EmberIgniterComponent` на пассивке огневика (в ядро не
      зашивали: наложение эффекта — контент, а не симуляция)
- [x] Поджог — 30/сек flat, 5 с, Refresh, `_damagePctTargetMaxHp` = 0
- [x] Воспламенение — 15 за стак «Углей», огнём, урон считается ДО сброса стаков
- [x] Мана Мечника — 100 запас, 60 стоимость, 8 за попадание, потолок 10/сек, КД снят
- [x] Тесты — расщепление, накопление и сход «Углей», детонация по стакам, множитель огня
- [ ] Замер стендом + сверка с коридором — **ждёт зелёной сборки**

## Статус

Код, ассеты и документация готовы. Прогон тестов и замер заблокированы: параллельная сессия держит
проект некомпилируемым (`RunModeBarView`/`UiPreviewCatalog`, до того `UnitView`). Combat/Data
собираются чисто — ошибок из моих сборок в консоли не было ни разу.

**Что осталось сделать, когда сборка позеленеет:** прогнать EditMode (ждут 4 новых теста + один
переписанный), затем стенд — DPS-бенч, выживаемость и дуэли — и сверить Мечника с коридором 90-150
при фактическом вкладе. До замера числа модели считать предварительными.

## Готчи этого захода

- Расщеплённый удар = **два** `DamageRequest`. Разгон «Пылающих клинков» должен срабатывать
  **один раз** на удар, иначе темп копится вдвое быстрее.
- Детонация усилена «Углями» и сама же их сбрасывает — считать урон ДО сброса.
- Правка SO через MCP может откатиться при доменной перезагрузке — проверять файл на диске
  (поймано в этом заходе на Пастыре).
