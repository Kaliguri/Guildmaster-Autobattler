## 1. Архитектура и швы

- [ ] **A** — **DI без синглтонов (VContainer).** Ни одной точки глобального доступа; зависимости только
  инъекцией. Продаёт: тестируемость и отсутствие скрытого состояния — в Unity-проектах это редкость.
- [ ] **A** — **Развязка Combat → UI / Audio / VFX типизированным pub/sub (MessagePipe).** Боевое ядро не
  знает ни об экране, ни о звуке. Три скоупа контейнера, шина останавливается на боевой сборке.
  Где: код `Assets/_Project/Scripts/Game/*LifetimeScope.cs` + запись `journal/2026-07-30-the-bus-stops-at-the-combat-assembly`.
- [ ] **A** — **Persist-мир: сцена не выгружается между боями.** Отряд живёт, враги приходят и уходят,
  арена подменяется на месте (`SetArena`), камера и арена — в постоянном `WorldLifetimeScope`. Бой стал
  «командой живому симулятору», а не загрузкой сцены. Продаёт: решение с внятной причиной, не туториал.
- [ ] **B** — **Сервисы за интерфейсами как правило слоя:** `IAudioService`, `IInputService`,
  `ISaveService`, `IScreenShake`, `IDisplayService`, `IUnitBodyVisual`. FMOD и Input System из геймплея
  не дёргаются вообще.
- [ ] **B** — **Швы под сеть уже стоят, сети ещё нет:** `IReadyGate`, `IPlayerIntentSource`,
  `ILocalPlayer`. Правило: что дорого ретрофитить — кладём заранее, остальное не выдумываем.
- [ ] **C** — **`IFocusPointSource`** развязал боевую камеру от симуляции: камера больше не знает, что
  такое бой.

## 2. Боевое ядро — самое инженерное в проекте

- [ ] **A** — **Детерминированная симуляция на 30 Гц с фиксированным тик-ордером.** Один сид даёт один
  бой; ретрай воспроизводится точно. Продаёт: детерминизм под кооп — то, на чём ломаются взрослые
  проекты.
- [ ] **A** — **Тик как один момент:** двухфазность (решения → коммит), закон видимости внутри тика,
  урон и хил применяются одним коммитом. Никто внутри тика не видит половину применённых изменений.
  Где: [tick-resolution.md](wiki/tech/40-planning/tick-resolution.md).
- [ ] **A** — **Лента боя: симуляция пишет вперёд, показ читает позади.** Сим уходит на 10 секунд
  вперёд и складывает события в ленту, картинка отстаёт — и поэтому щит успевает подняться ДО удара, а
  slowmo начинается ДО смерти. Лаг — свойство БОЯ, не камеры, и бой заканчивается, когда заканчивается
  ПОКАЗ. Мой фаворит на роль главного кейса.
  Где: [lookahead-presentation-lag.md](lookahead-presentation-lag.md).
- [ ] **A** — **30 Гц — частота симуляции, а не картинки.** Показ непрерывен при любом `TickRate`: поза
  атаки течёт по дробному тику, а не прыгает 30 шагами. Тик не поднимаем — вместо этого интерполируем.
- [ ] **A** — **Система эффектов producer → consumer** с тегами, стакингом и двумя уровнями
  реактивности; внутренняя очередь событий и реактивные компоненты.
  Где: код `Assets/_Project/Scripts/Combat/Effects/` + запись `journal/2026-07-30-effects-are-ordered-by-id-and-attributed-by-weight`.
- [ ] **B** — **Displacement как эффект, а не спец-система:** нокбэк, длительность полёта от дистанции,
  удар о стену останавливает полёт и роняет цель, скорость полёта — на источник.
- [ ] **B** — **Separation, симметричная относительно зеркала.** Баг нашёлся бенчем (BAL-014):
  расстановка слева и справа давала разный исход, включая вырожденное направление. Плюс из канонического
  порядка убрана аллокация. Продаёт: детерминизм проверяется измерением, а не верой.
- [ ] **B** — **AI-шов решения:** `ProfileBrain` / `BrainSystem` вместо «системы таргетинга», AI-пресеты
  живут контентом. Есть тест-гейт на детерминизм «мозгов», разнесённых по тикам.
- [ ] **C** — **Анти-лавина:** кап догоняющих тиков за кадр рендера, чтобы просадка не сворачивалась в
  спираль. Отличает работающую фикс-степ петлю от учебной.
- [ ] **C** — **Кадр существует, даже если сим ни разу не тикнул** — иначе первая же пауза гасит картинку.

## 3. Данные и контент-слой

- [ ] **A** — **Три слоя: SO (авторинг) → baked POCO (симуляция) → DTO (сейв и сеть).** Связь только
  строковым id `domain.name` из закрытого перечня домена; доступ через реестр `IContentDatabase` —
  единственный шов код↔контент. Продаёт: id переживает сеть, сейв и Workshop; шов под моды уже стоит.
- [ ] **A** — **Список того, что запрещено навсегда, и почему:** Odin **Serializer** (blob, AOT,
  конфликт с netcode), `AnimationCurve.Evaluate` в тике симуляции (кривые бейкаются), `Resources.Load`
  и статический доступ к конфигам, тихий code-fallback при null-конфиге. Odin **Inspector** при этом
  разрешён. Продаёт: инварианты как артефакт, а не как настроение.
- [ ] **B** — **Валидация контента — EditMode-тесты**, а не рантайм-варнинги, которые никто не читает.
- [ ] **B** — **Стат-авторинг абсолютом через `ModifierOp.Override`,** и осознанно ОТКЛОНЁННЫЙ рефактор
  в отдельный `BaseStats`: работает, покрыто тестами, миграция всех ассетов дороже выигрыша в
  эстетике. Продаёт умение не рефакторить — редкое.
- [ ] **B** — **Единый скейл статов ×10** проведён миграцией с сохранением TTK.
- [ ] **C** — **Spike на cross-assembly `SerializeReference`** для эффектов — граница сборок проверена
  экспериментом до того, как на ней построили систему.

## 4. Сейвы — маленькая система, много взрослых решений

- [ ] **A** — **Свой `JsonFileSaveService` вместо купленного Easy Save.** Причина: храним плоское
  durable-состояние по строковым id, а сильные стороны ES3 (графы объектов, ссылки на
  `UnityEngine.Object`, полиморфизм) решают проблему, которой у нас нет.
- [ ] **A** — **Корень сейвов — `LocalLow/Alebardium/Guildmaster/`, а НЕ `persistentDataPath`.**
  Последний растёт из `productName`, и переименование игры унесло бы сейвы игроков вместе с маской
  Steam Cloud. Инвариант держит тест `GameDataPathTests`. Продаёт: предвиденная беда, закрытая тестом.
- [ ] **A** — **Данные компьютера — отдельное хранилище вне облачной маски** (`Local/machine.json` за
  `IDisplayService`). Разрешение экрана с чужого ПК в худшем случае даёт чёрный экран на втором.
  Плюс готча: разрешение Unity пишет в реестр Windows до первой сцены, поэтому владельцем остаётся наш
  файл — мы применяем поверх.
- [ ] **B** — **Ключ сейва — путь в дереве** (`profiles/{id}/guilds/{gid}/run`); файл — конверт
  `schemaVersion` + `gameVersion` + payload; версия схемы объявлена атрибутом `[SaveSchema]` на DTO, а
  не полем внутри состояния.
- [ ] **B** — **Загрузка возвращает исход, а не бросает:** `Ok` / `Missing` / `Corrupted` / `TooNew` /
  `Unsupported`. Сейв из более новой версии игры не грузим И НЕ ЗАТИРАЕМ.
- [ ] **B** — **Атомарная запись** через временный файл плюс `.bak`; битый файл уезжает в `.corrupt`, а
  не удаляется.
- [ ] **C** — **Служебные суффиксы идут ПОСЛЕ расширения** (`run.json.bak`), потому что маска Steam
  Auto-Cloud — `Saves/**/*.json`, и она не знает, кто писал файл. Идеальная крутая мелочь.
- [ ] **C** — **`Vector2` требует своего конвертера в Newtonsoft**, иначе сериализатор уходит в рекурсию
  по `normalized`. Из тех готчей, которые находят один раз в жизни.

## 6. Презентация и анимация — техническая сторона

- [ ] **A** — **`TimeScaleService` как арбитр времени:** часы одни, желающих замедлить много — hitstop,
  финишер, пауза, дев-оверлей. Арбитр вместо гонки за `Time.timeScale`.
- [ ] **A** — **Death shatter по пиксельной сетке спрайта:** осколки нарезаются по плотным видимым
  границам, псевдо-3D кувырок, цветовые фазы, дрейф вверх. Не партикл-система, а разбор спрайта.
- [ ] **B** — **Хит-флеш переписан на официальный URP 2D sprite shader**, потому что подмена материала
  в рантайме ломала 2D SRP batching. Продаёт: понимание цены «просто мигнуть белым».
- [ ] **B** — **Скелетная анимация на трансформах:** названные точки вращения, кости, узел хвата
  предмета с калиброванным нулём (ноль = прямой угол к руке). Ничего не куплено.
- [ ] **B** — **Шов `IUnitBodyVisual`:** тинт, вспышка и осколки идут через шов, поэтому цельный спрайт и
  скелет взаимозаменяемы, а `SpriteRenderer` не торчит наружу.
- [ ] **B** — **Порядок частей тела имеет одного владельца и один экран** — draw-order перестал быть
  разлитым по префабам.
- [ ] **C** — **Y-сортировка тел по мировой Y** против мигания при равном сорт-ордере.
- [ ] **C** — **Кривая пишется целиком:** недостающую ось Unity молча дописывает нулём, поэтому позиция
  и повороты пишутся всеми осями сразу. Из этой готчи родился валидатор клипов.
- [ ] **C** — **Валидатор ловит выворот локтей и колен** — «наизнанку» стало ошибкой сборки, не вкусовщиной.
- [ ] **C** — **Пул `FloatingText` с null-guard на разрушении при выходе из play-mode** — мелочь, но
  именно такие исключения портят каждый выход из игры.

## 9. Инфраструктура и CI

- [ ] **A** — **CI с одним обязательным гейтом:** `changes` (paths-filter) → тесты + сборка плеера →
  `ci-gate`. Сборка гоняется только на PR и master, потому что дороже тестов, а dev ими и так закрыт.
  Продаёт: CI, спроектированный под цену, а не «включили всё».
- [ ] **A** — **Прогон Unity без открытого редактора — теневой проект.** Своя `Library` вне репо поверх
  junction-ссылок на живые папки (права администратора не нужны), `ProjectSettings` и `Packages`
  зеркалятся копией, потому что Unity в них пишет. Тесты и бенчи больше не требуют закрыть редактор.
- [ ] **A** — **Готча ложного зелёного:** `& unity -batchmode` возвращает управление сразу (это GUI-процесс),
  `$LASTEXITCODE` берётся от предыдущей команды — и скрипт печатал «tests PASSED», не создав файла
  результатов. Лечится `Start-Process -Wait` и проверкой по артефакту, а не по коду выхода. Лучшая
  короткая история этого проекта.
- [ ] **B** — **Сборка Standalone на Linux-раннере**, потому что Standalone у нас на Mono (IL2CPP задан
  только для Android) — и в комментарии написано, что переезд на IL2CPP потребует windows-раннера.
  Продаёт: инженер знает, чем платит за каждый выбор раннера.
- [ ] **B** — **Отдельные кэш-неймспейсы для job'ов:** два job'а на одном ключе `Library` гонятся друг с
  другом. Плюс освобождение диска перед сборкой, потому что образ раннера не оставляет headroom.
- [ ] **B** — **Кооп тестируется в редакторе через MPPM** — до 4 виртуальных игроков без билда.
- [ ] **C** — **`.gitattributes` под Linguist**, чтобы GitHub не считал проект набором шейдеров, и TMP-атласы
  помечены бинарными, чтобы не пухли диффы.
- [ ] **C** — **Готча пакетов:** Easy Save тянет `com.unity.visualscripting`, и удаление пакета роняет
  компиляцию — при том что сам ES3 из нашего кода не вызывается (у него нет asmdef).
