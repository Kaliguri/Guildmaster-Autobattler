# ТЗ для пиксель-художника — боевые юниты Guildmaster

> Кооперативный автобаттлер-рогалик (Unity, PC). Юниты сражаются на арене **автономно** (без микроконтроля), поэтому **читаемость и джус наблюдателя — приоритет №1**: бой должен быть приятно смотреть. Ниже — единый свод стиля и технических требований, чтобы весь ростер выглядел как одна игра.

---

## 0. Эталон стиля (это канон, всё меряем по нему)

Стиль игры = **собственные спрайты проекта FewSeconds-ManyDeaths** (приложены отдельно):
`Aegis (Shield Bearer)`, `Rifleman`, `Chess Master`, `Skeleton Priest`.

Что из них считывается как обязательные признаки стиля:
- **Проекция: корпус повёрнут на 15–25° от анфаса**, голова почти анфас, камера слегка приподнята
  (~25°). НЕ боковой профиль, НЕ строго сверху, и НЕ выраженные три четверти — поворот именно
  малый. Оружие и щит рисуются **плашмя к камере**, в своём ракурсе, независимо от корпуса.
  Обоснование и рефы — [`docs/view-angle-progress.md`](../view-angle-progress.md).
- **Жирный тёмный контур** (near-black, чуть уведён в синеву, не чистый чёрный `#000`).
- **Тени в тёмный сине-фиолетовый** (hue-shift), а НЕ в серый. Примеры теней из рефов: `#1c1d30`, `#222034`, `#2e1e2a`.
- **Скупая палитра: 8–14 цветов на юнита.** У рефов реально 6–11.
- **Один акцентный цвет на юнита** (тил у Aegis, золото у Priest) — держит фокус.
- **Почти-белые блики**, дозированно.
- **Пропорции около-реалистичные со слабой стилизацией** (решение 2026-07-29): голова 1/6 роста,
  ноги — половина фигуры. Не «героическая» крупноголовость и не строгий анатомический канон (1/7.5);
  читаемость добирается силуэтом, контуром и размером оружия, а не увеличением головы.
- **Выразительная поза и жест обязательны** — асимметрия, вес, характер. Симметричные «манекены» не принимаем.
- **Единый источник света на весь ростер** — рекомендуем сверху-слева.

Тест приёмки силуэта: залей спрайт сплошным чёрным — **роль юнита должна узнаваться по силуэту** (танк со щитом ≠ лучник ≠ маг).

## 1. Технические требования (жёсткие)

| Параметр | Значение |
|---|---|
| Высота фигуры | **три тира: 64 мелкий · 96 крупный · 128 большой** (от стоп до верха головы). Человек-юнит и герои — **96** |
| Канвас кадра | по тиру: 96×96 · **144×144** · 192×192 — фигура плюс место под замах и древко |
| Пропорции | **около-реалистичные, слабая стилизация:** голова 1/6 роста, пах на середине роста (ноги = половина фигуры). Мелкий тир 64 — 1/5.3 по необходимости читаемости |
| Размеры частей | пофрагментная сетка — [`docs/view-angle-progress.md`](../view-angle-progress.md) §«Сетка размеров частей». Этот документ её НЕ дублирует |
| Якорь/пивот | **центр стоп на фиксированном пикселе** (напр. x=32, y=58) — ОДИНАКОВО у всех юнитов и во всех кадрах анимаций. Критично: иначе юнит «дрожит» в движке. |
| Фон | прозрачный, **чистая альфа** — без полупрозрачного «мыла» по краю, без сглаживания в фон |
| Направление | **east (лицом вправо)** — канон; влево получаем флипом в движке (см. §4, «решения») |
| Свет | единый, сверху-слева, на весь ростер |
| Палитра | из общей **мастер-палитры** (§5), не выдумывать произвольные цвета |

**Формат сдачи:**
- Исходник **`.aseprite`** со слоями (не сведёнными): `outline` / `base` / `shadow` / `highlight` / `weapon` / `shield` (или аналогично). Аниматор в Unity и мы должны иметь возможность править по слоям.
- Экспорт **PNG спрайт-листами по анимациям** (горизонтальная полоса, ячейка строго равна канвасу тира: 96×96 · 144×144 · 192×192) + при необходимости покадрово.
- Именование: `unit_<id>_<anim>.png` (лист) и `unit_<id>_<anim>_<NN>.png` (кадр). `<id>` — латиницей.
- Для каждой анимации указать **тайминг** (кадров и мс/кадр или FPS).

**Соответствие миру:** 1 юнит мира = 1 м, рост человека ~1.7 м. Спрайт 64px рассчитан под это — держите общий масштаб «человек занимает ~X px по высоте» единым по ростеру, чтобы юниты были соразмерны.

## 2. Набор анимаций (на боевого юнита)

| Анимация | Кадры | Луп | Заметки |
|---|---|---|---|
| `idle` | 4–6 | да | дыхание/лёгкое покачивание, стойка «наготове» |
| `walk` | 6–8 | да | движение к цели |
| `attack_a` | 6–8 | нет | **основная авто-атака**, с геймфилом (см. ниже) |
| `attack_b` | 6–8 | нет | второй вариант атаки (визуальное разнообразие) |
| `hurt` | 3–4 | нет | флинч/отхил от урона |
| `death` | 6–8 | нет | оседание/падение, финальный кадр — «труп»/растворение |
| `cast` (опц.) | 6–10 | нет | для магов/саппортов вместо/вдобавок к attack |

**Геймфил атаки (важнее всего):** чёткая дуга **замах (anticipation) → удар (impact) → возврат (recovery)**.
- В кадре удара **оружие выходит за габарит силуэта** (вынос + «смир»/смазанный кадр).
- Должен быть один **выразительный пик-кадр удара** — движок повесит на него хитстоп/вспышку/тряску, поэтому он должен быть самым сочным.
- Стопы во время атаки/idle **стабильны** (не плавают) — иначе дёргается пивот.

**Враги:** минимум `idle` + `attack_a` + `hurt` + `death`; мелкий моб — можно `idle` + `attack` + `death`.

**Переиспользование:** `idle` и `attack_a` каждого юнита идут ещё и на **карточку в наградах/лоадауте** (карточка = анимированный спрайт, не иконка) — поэтому эти две обязаны читаться и вне боя.

## 3. Объём и порядок работ

1. **Сначала — один эталонный юнит: Защитник-щитоносец** (танк, круглый/каплевидный щит + меч, средняя броня, низкое фэнтези). Делаем его как «золотой образец»: базовый спрайт → апрув стиля/палитры/пивота → полный набор анимаций → апрув.
2. Только после апрува эталона — **массовое производство остального ростера** по утверждённым правилам.
3. Ростер (детали в GDD): ~16 героев-реликвий + враги (фракции/элиты/боссы). Финальные списки и приоритет — по согласованию.

## 4. Решения за заказчиком (подтвердить до старта)

Эти развилки сильно влияют на объём/цену — фиксируем явно:

1. **Направления.** Рекомендуем **east + флип** (одно направление, налево — зеркалим в движке). Альтернативы дороже: 4 стороны (S/E/W/N) или 8. Для нашей боёвки «команда против команды» одного направления, как правило, хватает. → *подтвердить.*
2. **Точный набор анимаций и число кадров** на тир юнита (герой / рядовой враг / элита / босс). Выше — базовая рекомендация. → *подтвердить/урезать.*
3. **FPS/тайминги** анимаций (или отдаём на вкус художника с нашим апрувом). → *подтвердить.*
4. **Нужен ли отдельный «портретный» кадр** для UI-карточек, или хватает боевых `idle`/`attack`. Рекомендуем — хватает. → *подтвердить.*
5. **Размер и приоритет ростера** для оценки бюджета. → *дать список.*

## 5. Стартовая мастер-палитра (снята с ваших рефов, художник дошлифует)

Общая на весь ростер, чтобы юниты были из одного мира. Ramp = тень → база → свет.

```
Контур:      #0a0a12
Тень (deep): #1c1d30   #222034
Сталь:       #2d3146  #565e72  #8c96aa  #c6cdda
Синее сукно: #202e4a  #34507a  #5878a8
Кожа/ремни:  #302018  #5c3a28  #8c643e
Дерево:      #3c281a  #68482c  #966e46
Кожа тела:   #78522c  #b08058  #d8a878
Кость/седина:#a9896a  #c7c7c7
Акцент тил:  #377162  #76bfcc
Акцент золото:#a05725 #c9a859  #ffe300
Блик:        #e6e8ee
```

Правило: у каждого юнита **1 акцент** (тил/золото/иное) как фокус, остальное — из общих рампов.

## 6. Приложения (передать художнику)

- **Референсы стиля:** 4 спрайта FewSeconds (`Aegis`, `Rifleman`, `Chess Master`, `Skeleton Priest`) — исходники `.aseprite` и PNG.
- **Анти-референсы (планка, которую надо перебить):** наши тесты в PixelLab и болванка-greybox — примеры того, что «читается, но без души» (общий сток, плоскость, отсутствие жеста). Показать, чтобы задать нижнюю границу качества.
- Снятая палитра (§5), это ТЗ.

---

## 7. Критерии приёмки (чек-лист)

- [ ] Силуэт-тест пройден (роль узнаётся в сплошной заливке).
- [ ] Палитра — из мастер-набора, ≤14 цветов, тени hue-shifted (не серые).
- [ ] Единый пивот: стопы на фикс. пикселе во всех кадрах, юнит не дрожит.
- [ ] Читается на игровом масштабе.
- [ ] Корпус повёрнут на 15–25° от анфаса, оружие и щит плашмя; единый свет.
- [ ] Кадр удара выразителен, оружие выходит за силуэт, есть пик для хитстопа.
- [ ] Чистая альфа, кадр по канвасу тира, слоёный `.aseprite` + спрайт-листы.
- [ ] `idle`/`attack_a` читаются и вне боя (для карточек).
