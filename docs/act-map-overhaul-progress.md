# Act-Map Overhaul — журнал забега

Ветка: `feat/act-map-overhaul` (от `dev` = PR #20). Крупный оверхол карты акта + смежное.
Этот файл — git-журнал: решения / сделано / отложено / готчи, чтобы новая итерация подхватила.

## Задачи (из брифа Макса)

- **0. Графика юнита** — единый источник графики для карты-в-инвентаре и боя, чтобы тинт/прочее
  рендерилось везде; + расстановка Grok-спрайтов по чемпам (разница не только тинтом).
- **1. 12 точек до босса** — увеличить глубину акта. **РЕШЕНО: «12 узлов на пути» игрока** (не колонок).
- **2. Полноэкранная карта + фон** — карта и её фон на весь экран (кроме топбара).
- **3. Оформление карты** — пунктиры между узлами, вид в духе AtO/StS2, анимация перехода
  фишки от точки к точке (~1.5с; дабл-клик сильно ускоряет).
- **4. Выход из боя** — ревард НЕ автоматом; после победы ~2с delay → кнопка «К наградам» →
  по клику ревард (игрок может досмотреть добивание / переход сцены в тест-зону).
- **5. Зоны спавна** — акт делится на зоны по «этажам». **РЕШЕНО: моя схема 3 зон + якоря.**
- **6. Камера карты** — pan/zoom как в бою, единое управление/источник. **РЕШЕНО: world-space
  гибрид** (карта/узлы/пути/фон/VFX — в мире с боевой камерой; кнопки/тултипы/топбар — UITK поверх).

## Порядок работы (утверждён)

Сначала дешёвые изолированные победы, потом дорогой переезд карты:
**A: п.0 → B: п.4 → C: п.5+п.1 → D(крупная): п.6+п.2+п.3.**

## Ключевые решения

- **п.6 = world-space гибрид.** Генерация карты (`MapGenerator`/`MapState`/`MapTraversal`) —
  чистая, ПЕРЕИСПОЛЬЗУЕТСЯ без изменений; переписывается только слой презентации карты.
- **п.1 = 12 узлов на пути** до босса (акт длиннее, ~13-14 колонок). Под это перемасштабировать
  зоны п.5.
- **п.0 бьётся надвое:** 0a — единый тинт (код, эта сессия); 0b — физрасстановка спрайтов
  (нарезка листов → аниматоры → per-champion `ViewPrefab` на ~15 юнитов) — отдельный арт-трек
  с визуальной приёмкой Макса, НЕ за один заход.

**Зоны и камера — решение Макса 2026-07-20 (важное):**
Требование: бой и карта имеют НЕЗАВИСИМЫЕ позицию и зум камеры («в бою отъехал вправо, на карте
влево — оба запомнились и не мешают»), и зоны разнесены в мире визуально.
- **Независимость состояния даёт четвёртая vcam, а НЕ разнесение.** Cinemachine у нас — три vcam
  с переключением `Priority` (`CameraModeController.cs:220`); каждая держит свой transform и свой
  `Lens.OrthographicSize`, неактивная стоит где стояла. `_mapCam` → «запомнилось» бесплатно, без
  словарей состояния. Именно поэтому `DriveManual(cam, …)` уже принимает камеру аргументом.
- **Разнесение зон всё равно делаем — но ради постобработки и света**, не ради камеры. Global Volume
  накрывает всё независимо от расстояния: свой bloom/грейдинг карте «в духе AtO» отдельно от боевого
  можно дать либо LayerMask-огородом, либо разнесением + два ЛОКАЛЬНЫХ Volume с боксами. Второе чище.
  Бонус: арену не надо гасить на время карты (она за кадром), и в Scene view видно устройство мира.
- **Разносить по Y вверх** (арена внизу, карта над ней): по X мир естественно растёт вширь при
  расширении арены — зоны бы съехались.
- **Дистанция — 2-3 высоты экрана, НЕ больше.** На больших координатах орто-проекция и партиклы ловят
  floating-point джиттер. «Другое место» визуально достигается уже на этом смещении.
- **ГОТЧА: Cinemachine Brain блендит между vcam.** При разнесённых зонах переход бой↔карта = полёт
  камеры через пустоту на пол-мира. Нужен явный **Cut** в Custom Blends для пар с `_mapCam`;
  боевые Action↔Overview бленд сохраняют.

  мировой сцены, а `RegisterComponentInHierarchy` ищет ТОЛЬКО в сцене своего скоупа (проверено по
  исходнику VContainer: `FindComponentProvider(… in scene …)`). Линк регистрируется в Root, слой
  привязывает себя к нему в `Start` (дочерний скоуп видит предка). Не сервис-локатор: явная DI-регистрация.
- **Ввод.** `InputContext.Map` (камера жива, боевых действий нет) + новая карта действий `Pointer`
  (указатель вынесен из `Deployment`, общий для расстановки и карты). Контекст выводится из ВЕРХА
  СТЕКА по `UiScreen.MapModeTag` — фаза боя тут молчит (карта вне боя → `BattlePhase.None`).
- **UI.** `MenuRouter.ShowMapSpace/HideMapSpace` — прозрачный Sheet `map-space` (`pickingMode=Ignore`),
  по состоянию `WorldMapSpaceChangedEvent` (владелец — chooser), подписка в `UiRootBootstrap`.
- **DI.** `RootLifetimeScope`: `WorldMapNodeChooser` как `IMapNodeChooser` (откат на UITK = замена
  этой одной строки), `WorldMapViewLink` как `IWorldMapView`. `WorldLifetimeScope`: `WorldMapView`.

**Проверено в play-mode (программно, реальным контрактом `ChooseAsync`):** 32-33 узла и 43-46 рёбер
рисуются, `CM Map` становится активной vcam, линк привязан из всех трёх скоупов, DI поднимается без
ошибок. Скриншот показан Максу — граф читается, цвета типов различимы.

### Готчи, найденные в D1 (важно для следующих шагов)

- **Shapes `Line.Start/End` — ЛОКАЛЬНЫЕ координаты объекта.** Слой карты смещён в свою зону мира,
  поэтому мировые точки туда класть нельзя: линии уезжают на величину смещения (ровно этот баг и был —
  узлы рисовались, рёбер не было). Лечение: объект линии ставится в первую точку, `Start = zero`,

- **`MeshRenderer.isVisible` и скриншот Game View врут, когда редактор не в фокусе.** Первый скрин
  вышел полностью чёрным, хотя всё рисовалось. Проверять картинку — прямым рендером с камеры
  (`manage_camera screenshot camera=Main Camera`), не через ScreenCapture.
- **`execute_code` в Unity MCP — тело метода:** `using`-директивы не компилируются, нужны полные имена.
  `IObjectResolver.Resolve` — не дженерик, звать `Resolve(typeof(T))`.
- Sheet-пространство карты прячет Page под собой — открытое главное меню при показе карты уходит.
  В забеге так и надо, но помнить при read-only просмотре карты из топбара.

## D3 — профиль акта, иконки, органичная раскладка, свобода камеры (`4224806e`, 430/430)

Четыре задачи Макса + важная поправка от него же по слоям.

- **ЧИСТОТА СЛОЁВ (поправка Макса, важно).** `MapNode` хранил `UiPosition` — понятие презентации, и на
  него же была завязана СЕМАНТИКА: зоны/якоря/тесты читали `UiPosition.x` как «этаж». Разложено:
  домен хранит только топологию (`Floor`, `Row`), координаты/центрирование/разброс считает презентер.
  Правило на будущее: в `MapNode` не должно появляться ничего про отрисовку.
- **Профиль ширины** (`MapGenConfig.EdgeColumnWidth`/`EdgeColumns` + Min/Max для середины): акт
  начинается узко (3), раздаётся к середине (4-6 рандом) и снова сужается к боссу. Пример реального
  забега: `1-3-3-4-6-6-6-4-6-6-4-3-3-1`.
- **`MapLayout`** (Presentation) — чистая тестируемая функция раскладки. Разброс НЕ хранится в данных:
  выводится хешем FNV-1a от `id узла + сид забега`. Поэтому стабилен между открытиями карты и переживает
  загрузку сейва, а домен о нём не знает. Сид отдаёт `WorldMapController` из `RunState.Seed`.
- **`MapIconSet`**-SO: тип узла → иконка + цвет подложки, правится в инспекторе. Иконки СКОПИРОВАНЫ в
  `Art/UI/Icons-gm/Map` (Honeti 32×32 Outlined + `Help` 16×16 под «?»), а не тянутся из пакета — иначе
  обновление Honeti ломало бы карту. Ассет `ScriptableObjects/Configs/MapIconSet.asset`, назначен на
  `WorldMapView` в WorldScene.
- **Свобода камеры**: пан разрешён на полэкрана за края карты (`_mapFreedom`), потолок отдаления в
  режиме Map считается по БОЛЬШЕЙ стороне зоны (карта широкая и низкая — ограничение по меньшей стороне
  не давало увидеть акт целиком).

### Готча раскладки (стоила бага, не потерять)

Сильный разброс по Y **ломает непересекаемость рёбер**: «монотонная лестница» гарантирует планарность
только на РОВНОЙ сетке. При разбросе 0.4 шага два соседа по этажу могут поехать навстречу, сблизиться
почти вплотную (шаг 3.6 − 2·0.4·3.6 = 0.72 при диаметре узла 1.0) — узлы слипались, рёбра
пересекались. Решение: разброс расщеплён на **дрейф ЭТАЖА целиком** (`FloorDriftY`, хеш от номера
этажа — колонка едет как единое) и **слабый разброс узла** (`JitterY`). Карта волнится, строй внутри
этажа цел. Тест `Resolve_KeepsRowOrderAndGapWithinFloor` держит это свойство на 50 сидах.

## D5 — акт всё ещё был по 2-3 узла: правился КОД, а играл АССЕТ (`3cdb69f5`, 433/433)

**Симптом:** профиль в коде уже 5-6, тесты зелёные, а в игре по-прежнему 2-3 узла на этаже (два раунда

`MapGenConfig`. Правка дефолтов в C# ассет НЕ меняет: старые значения (`MinColumnWidth=2`,
`MaxColumnWidth=3` из фазы C) остаются, новые поля приезжают пустыми. Все мои проверки строили

**Лечение:** значения в ассете обновлены (края 3 / середина 5-6) + `ActConfigAssetTests`, который
грузит ИМЕННО АССЕТ и проверяет профиль на 20 сидах. Реальный забег: `1-3-5-5-6-6-5-6-6-6-6-6-3-1`, 65 узлов.

**ПРАВИЛО НА БУДУЩЕЕ (стоило двух раундов play-QA):** если у настройки есть SO-ассет, менять дефолт в
коде НЕДОСТАТОЧНО — обновлять ассет и проверять ЧЕРЕЗ НЕГО. Тест на дефолтах кода такой дрейф не ловит
by design. Это же касается `MapIconSet`, `WorldCameraBlends`, `CombatFeelConfig` и прочих конфигов-ассетов.

## D6 — редизайн вида карты: префаб, палитра, дорожки-точки, маршрут (`f1037e5f`, `cea7f4a0`, `1e32950a`, 434/434)

## D7 — читаемость карты: короткие связи, ровные столбики, прямые пути (`5d90765a`, 435/435)

Раунд play-QA Макса по D6: пути читались кашей.

**ЗАМЫСЕЛ МАКСА (важный контекст, влияет на все будущие решения по карте):**
карта задумана как большая **КАРТА**, и широкие развилки — это СОДЕРЖАНИЕ выбора, а не издержка.
Планируются **биомы**: игрок выбирает не только «сколько элиток», но и через какие биомы идти.
Поэтому предложение сузить карту (модель StS с прокладкой K маршрутов) **ОТКЛОНЕНО Максом** —
и правильно: мой аргумент был про читаемость, его — про смысл выбора. 1-4 исхода из узла = норма,
больше 4 не нужно.

**Диагноз (мой, принят):** проблема была не в ШИРИНЕ, а в ДЛИНЕ рёбер. Лестница шагала случайно, и на
скачках ширины (5→7→3) один узел набирал веер диагоналей через полкарты.

**Сделано:**
- Связи ведутся **вдоль диагонали колонок**: указатели сравнивают ДОЛИ пройденного, а не индексы.
  `MaxEdgesPerNode` (4) — потолок исходов и входов. Проверено: макс 3-4 исхода, преобладают 1-2.
- **Разброс раскладки убран целиком** — этаж стоит ровным столбиком (прямое требование Макса).
  Живость даёт форма графа. Тест `Resolve_DiffersBetweenSeeds` заменён на пару:
  «этажи стоят столбиками» + «механизм разброса жив и завязан на сид, если его включат».
- **Сетка растянута** (StepX/StepY = 6.5/4.2) — узлам нужен воздух.
- **Пути прямые** (`_edgeCurve` = 0): изгиб случайной стороны заставлял соседние рёбра наезжать.

**БИОМЫ И ЦВЕТ (решить, когда дойдём):** в D6 принято «строго один тон на все узлы» — это про ТИП узла.
Биом — другая ось (регион карты), и он придёт ЗА ЦВЕТОМ. В ГДД уже заложено: `gdd/00-meta/roadmap.md:57`

## D8 — единое место настроек, снос UITK-карты, задник (`a1848687`, `2c8fae4d`, `b1ad37ad`, 435/435)

## D9 — такт, сердцебиение, туман, читаемость (`c2a4e837`, `402d880d`, 435/435)

- **Постобработка карты** — локальный Volume `MapPostFX` в зоне карты: виньетка, лёгкий грейдинг, bloom с

## D10 — лист вместо полотна, реестр эффектов, фикс DI (`40488d3f`, `3da57dfe`, 435/435)

**РЕГРЕССИЯ И ЕЁ ПРИЧИНА (важная готча).** Забег показывал БОЕВУЮ АРЕНУ вместо карты, хотя таб «Карта»
переключался. Причина — не камеры: `VisualTempo` имел конструктор `VisualTempo(float bpm = 84f)`.
**VContainer НЕ понимает значений по умолчанию** — он пошёл резолвить `System.Single`, не нашёл и не собрал
сервис; следом не собрался `WorldMapView` (зависит от такта), слой карты остался мёртвым.
Симптом был далеко от причины. Лечение: константа + `SetBpm`. Записано в память как
[[vcontainer-ctor-defaults]]. **Урок процесса:** правки DI обязаны проверяться поднятием play и резолвом —
компиляция и EditMode такое не ловят by design.

**Задачи Макса (реф — StS2):**
- **Карта = ЛИСТ**, а не залитый экран: полотно обтягивает граф с полями (`BackdropPadding` 1.6 → 1.08),
  за краем начинается фон. Размер листа = по графу с полями (решение Макса).
- **Рваный край** — в шейдере: шум вдоль периметра «откусывает» бумагу, край затёрт и потемнел.
  Пропорции листа передаются в шейдер (`_AspectX`), иначе на длинной карте рваность вытягивается
  вдоль в пологую волну, а поперёк остаётся частой.
- **Светлая желтовато-выцветшая бумага** с заметными потёртостями и зерном.
- **Виньетка листа снова включена** — теперь она осмысленна: лист ОГРАНИЧЕН, его края видно на экране
  (в D9 она была бесполезна на растянутом полотне).
- **Туман ВЫКЛЮЧЕН** («вообще не то, мб позже вернёмся»). Не удалён — гасится тумблером.

**Реестр эффектов `VisualToggles`** (+ `gm_fx`, `gm_fx_on/off/toggle/all`): одно место, где визуальные
эффекты гасят и возвращают, чтобы сравнивать «с ним и без». Зарегистрировано 5: `map.sheet`, `map.fog`,
`map.heartbeat`, `map.pathflow`, `post.map`.
**Почему реестр, а не экран с галочками** (обосновано Максу, принято): экран стоит вёрстки, локализации и
поддержки на каждый новый эффект; часть тумблеров (bloom, зерно, тряска) всё равно уедет игроку в настройки
как ДОСТУПНОСТЬ — вот там у них и будет UI. Строить панель сейчас = построить дважды.
Новый эффект подключается одной строкой `Register(id, описание, on => ...)`.

**Отклонено Максом:** «карта как лист на СТОЛЕ гильдмастера» (пропсы, свеча) — в пиксель-арте сомнительно
и требует художника. Взамен тех-вектор: дизеринг, процедурная сетка/роза ветров, чернила за фишкой.

## D11 — ровный пульс вместо сердца, стол под листом, возвращение Kenney (`e26ddbb9`, `6e2ac917`, 435/435)

**Пульс.** Макс отверг сердцебиение: нужно «обычное моргание в такт — то больше, то меньше, не быстрое,
но заметное». `IVisualTempo.Heartbeat` удалён вместе с единственным потребителем (двойной толчок читался

переименован в `map.pulse`. Поле переименовано через `[FormerlySerializedAs]`, значение в ассете прописано
руками (правило D5).

**Стол.** За рваными краями листа была пустота, которую камера заливала цветом очистки. Появился слой
`Table` (`TableZ = 2`, за листом): шейдер `Guildmaster/Map/Table` тайлит паттерн, красит его цветами
материала и накладывает маску света — карта лежит в тёплом пятне, углы кадра тонут. Ни одного
нарисованного пикселя: тайл `kenney_pattern-pack/pattern_63`, маска `kenney_light-masks/circle_a_streaks_noise`.
Это ответ на давнее «стол в пиксель-арте сомнительно» — стол собирается технически, а не рисуется.
Квад берётся с запасом `_tablePadding: 3.5` от листа: увидеть в кадре КРАЙ стола хуже, чем не увидеть
стола вовсе. Тумблер `map.table`.

**Kenney вернулся и наконец в git.** Пак жил в `Assets/` НЕ отслеживаемым — единственный такой
(Feel, Honeti, Cainos, Shapes всегда были в репе). Поэтому и пропал. 14 паков, 89 МБ, CC0.

Значит «непиксельность» ассета больше НЕ автоматический стоп-фактор — критерий сместился на

# Задачи N1-N3 — ЗАКРЫТЫ в D6 (историческая формулировка ниже)

Все три сделаны, детали и отклонения от исходной формулировки — в разделе D6 выше.
N2 по ходу дела вырос в редизайн вида карты: Макс отменил «префаб на тип» в пользу одного префаба,
отменил цветовое различие типов и добавил требования по дорожкам, маршруту и отклику.

## N1. Дев-команды для теста карты

Макс: «добавь команды для теста карты». Две штуки:
- **Вернуть фишку в изначальную позицию** на карте (сброс к стартовому узлу).
- **Свободный переход между точками в любой момент** — чтобы смотреть анимации, не проходя забег.

Реализация: в проекте есть Quantum Console (`QFSW.QC`, подключён в `Guildmaster.DevTools`) — команды
класть туда же, где прочие dev-команды. Дёргать `WorldMapController`/`WorldMapView`; учесть, что
`NodeClicked` сейчас поднимается ПОСЛЕ приезда фишки, а переход «просто посмотреть» не должен
уводить петлю в узел (то есть нужен путь анимации БЕЗ выбора — отдельный метод у слоя карты).

## N2. Иконки узлов — префабы + непрозрачные круги

Макс: «круги под иконками 100% непрозрачности; иконки сами меньше, чтобы помещались; лучше каждую
иконку как ПРЕФАБ (+ родительский основной префаб иконок) — дальше я сам всё настрою».
- Убрать полупрозрачность подложки (`BackingAlpha`, сейчас 0.75) → сплошной круг.
- Уменьшить иконку относительно круга (сейчас `MapIconSet.WorldHeight` = 1.1 при радиусе 0.6 — иконка
  почти равна подложке и вылезает).
- **Сменить схему: узел = ПРЕФАБ, а не собранный кодом Disc+SpriteRenderer.** Родительский префаб
  узла + по префабу на тип. Это ПРЯМАЯ просьба Макса — он хочет настраивать вид сам в инспекторе.
  Значит `WorldMapView` должен инстанцировать/пулить префабы вместо ручной сборки фигур, а `MapIconSet`
  становится набором префабов (или заменяется им).
  ВАЖНО: не подменять эту форму на «мне удобнее кодом» — конечная форма ассета решается ПОД ИГРУ
  (см. память `dont-dress-my-limits-as-principles`).

## N3. Ширина середины — настраиваемый ДИАПАЗОН рандома

Макс: «середина (5-6) — это реальный рандом при генерации забега; в конфиге должны мочь задать не
просто значение, а ОТ скольки ДО скольки оно рандомится».
Состояние на сейчас: поля `MinColumnWidth`/`MaxColumnWidth` в `MapGenConfig` УЖЕ дают такой диапазон,
и `MapGenerator.ColumnWidth` роллит `rng.NextInt(Min, Max+1)` независимо на каждый этаж. То есть
механика, похоже, уже есть — но Макс её так не увидел.
**Первым делом уточнить у Макса, чего именно не хватает.** Гипотезы: (а) непонятны имена/подача полей
в инспекторе `ActConfig` (нужен явный «диапазон» одним блоком, а не два числа вразнобой); (б) он хочет
диапазон и для ГОРЛОВИН тоже (сейчас `EdgeColumnWidth` — одно число); (в) хочет разные диапазоны на
разные зоны акта. Не додумывать — спросить.
