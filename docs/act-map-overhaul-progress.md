# Act-Map Overhaul — журнал забега

Ветка: `feat/act-map-overhaul` (от `dev` = PR #20). Крупный оверхол карты акта + смежное.
Этот файл — git-журнал: решения / сделано / отложено / готчи, чтобы новая итерация подхватила.

## Задачи (из брифа Макса)

- **0. Графика юнита** — единый источник графики для карты-в-инвентаре и боя, чтобы тинт/прочее
  рендерилось везде; + расстановка Grok-спрайтов по чемпам (разница не только тинтом).
- **1. 12 точек до босса** — увеличить глубину акта. **РЕШЕНО: «12 узлов на пути» игрока** (не колонок).
- **2. Полноэкранная карта + фон** — карта и её фон на весь экран (кроме топбара).
- **3. Оформление карты** — пунктиры между узлами, вид в духе AtO/StS2, анимация перехода
  фишки от точки к точке (~1.5с; дабл-клик сильно ускоряет).
- **4. Выход из боя** — ревард НЕ автоматом; после победы ~2с delay → кнопка «К наградам» →
  по клику ревард (игрок может досмотреть добивание / переход сцены в тест-зону).
- **5. Зоны спавна** — акт делится на зоны по «этажам». **РЕШЕНО: моя схема 3 зон + якоря.**
- **6. Камера карты** — pan/zoom как в бою, единое управление/источник. **РЕШЕНО: world-space
  гибрид** (карта/узлы/пути/фон/VFX — в мире с боевой камерой; кнопки/тултипы/топбар — UITK поверх).

## Порядок работы (утверждён)

Сначала дешёвые изолированные победы, потом дорогой переезд карты:
**A: п.0 → B: п.4 → C: п.5+п.1 → D(крупная): п.6+п.2+п.3.**

## Ключевые решения

- **п.6 = world-space гибрид.** Генерация карты (`MapGenerator`/`MapState`/`MapTraversal`) —
  чистая, ПЕРЕИСПОЛЬЗУЕТСЯ без изменений; переписывается только слой презентации карты.
- **п.1 = 12 узлов на пути** до босса (акт длиннее, ~13-14 колонок). Под это перемасштабировать
  зоны п.5.
- **п.0 бьётся надвое:** 0a — единый тинт (код, эта сессия); 0b — физрасстановка спрайтов
  (нарезка листов → аниматоры → per-champion `ViewPrefab` на ~15 юнитов) — отдельный арт-трек
  с визуальной приёмкой Макса, НЕ за один заход.

- Выход из боя: исход в `Combat/CombatSimulation.cs:619` (`CheckOutcome`→`OnBattleEnded`);
  награда открывается в ТОТ ЖЕ кадр через `BattleNodeFlow.cs:33-37` → `RewardPresenter`.
  Шов под п.4 (delay+кнопка) = `BattleNodeFlow.Run` между исходом и `PresentAsync`. Готовый

  ГОТЧА #37: всюду протянут `ctx.Cancellation` — любую задержку делать через
  `AttachExternalCancellation(ct)`, иначе «В меню» подвесит петлю.
- Графика юнита: единый источник = `UnitData.ViewPrefab` (бой `CombatPresenter.cs:229`,
  карточка `UI/Components/RelicCardVisualRig.cs:64`). Тинт — асимметрия: бой берёт из
  рантайм-хеша имени (`CombatPresenter.TintFor`), карточка тинт НЕ применяет. Поля цвета в
  данных не было. Спрайты в `Art/Sprites` ЗАКОММИЧЕНЫ (~5219 файлов). ViewPrefab — один
  placeholder `Prefabs/UnitView.prefab` на всех. Чемпионов-`RelicData` ~10 + 5 врагов.
  Grok-маппинг спрайт→персонаж уже в `docs/wiki/research/sprite-recommendations.md`.

## Готчи

- Спрайт юнита — на кастомном HitFlash-шейдере: `SpriteRenderer.color` подхватывается только
  после первой записи `MaterialPropertyBlock` (`UnitView.PrimeFlashBlock`). Тинт в карточке
  ставить С MPB-праймом, иначе молча не отобразится на статичном рендере.
- CoreScene.unity мержится плохо — git add точечно, не add -A (в дереве постоянный churn).

## Сделано

- **Фаза A / п.0a — единый резолвер тинта (готово, 418/418 EditMode).**
  - `UnitData`: поле `_tint` (Color, дефолт White) + `Tint` + `ResolveBodyTint()` — единый источник
    цвета тела. White = «не задан» → дев-фолбэк HSV от имени SO (как раньше делал только бой).
  - `CombatPresenter.TintFor` → зовёт `ResolveBodyTint()` (убран локальный хеш-дубль).
  - `RelicCardVisualRig`: `ApplyBodyTint()` красит `UnitView._sprite` (рефлексией) тем же цветом,
    с MPB-праймом `_FlashAmount=0` (иначе HitFlash-шейдер игнорит `.color` на статичной карточке).
  - Итог: болванки-чемпионы теперь различаются цветом И в бою, И в инвентаре (раньше в карточке
    тинта не было вовсе). Дизайнер может задать явный `_tint` на `RelicData` — подхватится везде.
  - ОСТАЛОСЬ в п.0: 0b — физрасстановка Grok-спрайтов (отдельный арт-трек, с приёмкой Макса).

- **Фаза B / п.4 — выход из боя через кнопку «К наградам» (готово, 418/418 EditMode).**
  - `BattleNodeFlow`: между победой и наградой — `Delay(postWinDelaySeconds, ct)` (дефолт 2с,
    досмотр добивания) → `WaitForContinueAsync("ui.reward.continue", ct)` (кнопка-мост) → цикл
    наград. Награда БОЛЬШЕ не выскакивает автоматом в кадр смерти врага.
  - Инъекция `IContinuePresenter` через `NodeResolver` (DI резолвит по типу, регистрация не тронута).
  - Кнопка «Продолжить» ПОСЛЕ награды (узел→карта) — прежняя, в `ActRunner`, не дублирована.
  - Delay — DeltaTime (пауза забега замораживает таймер); всё на `ctx.Cancellation` (#37).
  - Loc-ключ `ui.reward.continue` (RU «К наградам», EN «—») через `ContentLocalization.SetValue`.
  - Тесты `BattleNodeFlowTests` адаптированы: фейк `ImmediateContinue` + `postWinDelaySeconds:0`.
  - Приёмка потока (бой→досмотр→кнопка→ревард) — play-mode Макса; delay ещё можно подкрутить.
  - Порядок delay=2с сейчас захардкожен дефолтом конструктора → позже вынести в ActConfig-SO (фаза C).
