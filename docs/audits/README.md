# Аудиты проекта — методология

Периодический внешний код-/дизайн-аудит. **Один аудит = несколько независимых прогонов разными AI-агентами по одному и тому же scope, затем синтез их мнений в общий вывод.**

## Структура

```
audits/
├── README.md            ← этот файл (методология)
└── YYYY-MM-DD/          ← один раунд аудита (по дате)
    ├── <agent>.md        ← сырой отчёт одного агента (по файлу на агента)
    └── summary.md        ← синтез: консенсус, спорное, план действий
```

## Именование

- Папка раунда — ISO-дата `YYYY-MM-DD` (сортируется хронологически).
- Файл агента — короткое имя модели: `opus-4.8.md`, `codex-5.3.md`, `grok.md`, `composer.md`, ...
- Синтез — всегда `summary.md`.

## Как провожу аудит

1. **Scope.** Зафиксировать, какие папки/системы смотрим — одинаковый scope для всех агентов.
2. **Независимые прогоны.** Прогнать N агентов по этому scope; каждый пишет свой отчёт в `<agent>.md`. Агенты **не видят** отчётов друг друга — чтобы мнения не схлопывались.
3. **Сведение.** Выделить: (а) консенсус (нашли несколько), (б) спорное/противоречивое, (в) уникальные находки.
4. **summary.md.** Приоритизированный список (P0/P1/P2): что подтверждено по коду, что отклонено и почему.
5. **В работу.** Actionable-пункты завести в бэклог или в соответствующий тех-док вики (например changelog `../wiki/tech/code-guide/07. Техдолг, решения и changelog.md`).

## Принципы

- **Сверять по коду.** Агенты читают снимок на момент прогона; рабочее дерево может уйти вперёд. Каждую находку проверять по актуальному коду перед правкой.
- **Дедуп — на синтезе.** Схлопывание дублей делаю сама на шаге 3, не поручаю агенту.
- **Отчёты агентов — исторический артефакт.** Не редактируются задним числом: пути, номера и факты в них — на момент аудита.
