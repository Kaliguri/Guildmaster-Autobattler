## План

### Ф1. `compile-check.ps1` — проверка компиляции без Unity **[в работе]**

Прототип проверен вручную 2026-07-31: боевая сборка собирается за **2.1 сек** без редактора, ноль
ошибок. Механизм — Roslyn из установки Unity (`Editor/Data/DotNetSdkRoslyn/csc.dll`) плюс готовые
команды компиляции, которые Unity сама пишет в `Library/Bee/artifacts/*.dag/*.rsp`.

Что делает скрипт:
- определяет затронутые сборки по `git diff` (или берёт указанные / все);
- строит топологический порядок по ссылкам в `.asmdef`;
- для каждой сборки берёт её `.rsp`, подменяет выход на временную папку вне репозитория, а ссылки
  на уже пересобранные наши сборки — на свежие временные;
- **список исходников берёт с диска, а не из `.rsp`** — иначе новые файлы остаются невидимыми;
- опционально генерирует `.meta` для новых `.cs` (простой YAML с guid) — снимает готчу
  «нет `.meta` — null-компонент».

Ограничение, которое надо назвать вслух: `.rsp` рождается в Unity. Пока не менялся состав пакетов
или сборок, он актуален; после добавления пакета файл надо обновить открытием редактора. Скрипт
обязан это заметить и сказать, а не собрать по устаревшим ссылкам молча.

### Ф4. Что накапливается — **профайлер не помог, но кривая построена** ◐

**Editor Iteration Profiler не работает на Unity 6.** Пакет (`0.1.2-preview`, последняя правка 2020)
поставился и завёлся — окно открылось, `EditorProfilingEnabled` встало в `true`, — но после трёх
перезагрузок собрал **ноль событий**. Разбивки по классам от него не будет; пакет удалён, следов в
`manifest.json` и `packages-lock.json` не осталось.

**Зато кривая деградации построена по логу, и у неё есть порог.** Прошлая сессия, номер перезагрузки
против её цены:

```
#1: 1.0 c    #61: 9.3 c    #141: 15.7 c    #221: 36.0 c
#21: 8.3 c   #81: 10.9 c   #161: 24.3 c    #241: 44.4 c
#41: 8.9 c   #121: 13.6 c  #201: 30.6 c    #261: 53.6 c
```

До сотни рост пологий, дальше ускоряется. Проверено на живой сессии: тридцать с лишним перезагрузок
держатся в коридоре 9.7–14.9 с без всякого роста — то есть порог реален, а не выдуман.

**Улика, на которую стоит смотреть дальше:** в той сессии 860 срабатываний обвязки тест-раннера и
**24 живых экземпляра `TestRunnerApi`** в памяти редактора прямо сейчас — по одному на прогон, никто
их не убирает. Прогоны тестов в редакторе — главный кандидат в источники мусора, и лечится это
бесплатно: гонять их теневым проектом (`run-tests.ps1 -Where Shadow`), а не в живом редакторе.
