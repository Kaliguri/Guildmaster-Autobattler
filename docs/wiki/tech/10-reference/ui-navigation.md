## 1. Три слоя (границы)

| Слой | Форма | Кооп-природа |
|---|---|---|
| **Навигация** | стек типизированных экранов + слои-контейнеры; единственный владелец видимости И ввода | **client-local, НЕ реплицируется** — у каждого игрока своё «какое окно открыто» |
| **Презентация** | тупые View, POCO ViewModel | локальная |
| **Данные** | единый источник (`RunState`/сервисы); UI мутирует только командами-интентами (MessagePipe) | host-authoritative шов (репликация — позже) |

Реплицируется **состояние мира, а не состояние взгляда**. Это причина, по которой навигация
принципиально client-local.

## 2. Навигатор: стек + типы экранов

`UiNavigator` (`Assets/_Project/Scripts/UI/Navigation/UiNavigator.cs`) — POCO, регистрируется в
`RootLifetimeScope` как singleton. Держит `List<UiScreen>` (`[0]` низ, `[last]` верх). Владелец
видимости нижних экранов и глушения геймплейного ввода.

**`ScreenKind`** (`Navigation/ScreenKind.cs`) определяет ПОВЕДЕНИЕ экрана — вместо CSS-классов-флагов:

| Тип | Прозрачность | Глушит геймплей | Прячет нижний | Примеры |
|---|---|---|---|---|
| **Page** | непрозрачный | да | да (структурно) | карта, магазин, ивент, награда, главное меню |
| **Modal** | scrim | да | нет | пауза, настройки, подтверждение |
| **Sheet** | прозрачный | **нет** (мир жив через `PointerOverUI`) | нет | инвентарь, тест-зона |

**API (эскиз):** `Push`/`Pop`/`PopAll`; `ShowAsync<TResult>(screen, ct)` для flow-экранов
(награда/карта/магазин/…) — гарантирует **ровно один резолв** (явный выбор / `DefaultResult` при
снятии без выбора / отмена забега по токену). `Top`, `IsOpen`, `ActiveModeTag` (тег верхнего
НЕ-Modal экрана — для подсветки таба), событие `Changed` (топбар/backdrop подписываются вместо
поллинга структуры).

Экраны роутера (`MenuRouter`) — `RouterScreen`/`RouterResultScreen<T>`: обёртка над билдерами UXML
с честным `ScreenKind`. `MenuRouter` строит и проводит экраны, а стек/видимость/ввод делегирует
навигатору. Отдельного `IMenuRouter`-интерфейса нет (растворён — единственный потребитель берёт
класс напрямую).

## 3. Слои-контейнеры (z-порядок = порядок добавления)

`UiRootBootstrap` создаёт в корне единственного `UIDocument` восемь слоёв-контейнеров
(`AddLayer`, все `pickingMode = Ignore`, z по порядку `Add`):

```
[0] layer-backdrop       — задний фон забега (виден на не-боевых экранах)
[1] layer-battle-center  — «Начать»/таймер боя (ЗА экранами — QA #19/#23)
[2] layer-screens        — Page/Sheet навигатора (ПОД топбаром)
[3] layer-topbar         — RunModeBar: виден весь забег, кликабелен над обычными экранами
[4] layer-modal          — Modal навигатора (НАД топбаром; fullscreen-scrim накрывает и топбар)
[5] layer-cursors        — задел (live-курсоры партнёров)
[6] layer-tooltip        — задел (тултип-система)
[7] layer-system         — задел (тосты/фид/dev-консоль)
```

Навигатор кладёт экран по `ScreenKind`: `Page`/`Sheet` → `layer-screens`; `Modal` → `layer-modal`.
Слои `[5]–[7]` создаются как заделы (ссылки на них пока не хранятся — наполнятся при реализации
курсоров/тултипов/тостов). Императивный z-порядок (`BringToFront` каждый кадр, `SendToBack`,
репарент `battle-center`) снят — z даёт порядок слоёв.

Топбар (`RunModeBarView`) — persistent-слой, не экран стека; пересобирается при смене локали.
Прежняя панель `RunTopBarView` и её интерфейс `IRunTopBar` снесены (2026-07-19); единственная
панель забега — `RunModeBarView`.

## 4. Ввод и видимость = f(верх стека, фаза боя)

Сердце реформы. `GameplaySuppressed` и `Context` (`IInputService`,
[[tech/10-reference/input-camera|Reference - Input & Camera]]) не мутируются несколькими хозяевами —
они **вычисляются** навигатором (`UiNavigator.SyncInput`):

```
modal = Top != null && Top.Kind != Sheet
GameplaySuppressed = modal
Context = modal ? Menu : WorldContextOf(clock.Phase)

WorldContextOf: Deployment → Deployment; Fighting → Combat; None → None
```

`SyncInput` дёргается на каждое изменение стека (Push/Pop/PopAll/резолв) И по подписке на
**`IBattleClock.PhaseChanged`** (`Assets/_Project/Scripts/Data/Definitions/BattleClock.cs`).
Событие поднимает `BattleSession.SetPhase` только на РЕАЛЬНОЙ смене фазы; навигатор подписан в
конструкторе (реализует `IDisposable` → отписка при разрушении скоупа).

**Навигатор — единственный писатель контекста** (снос K8, 2026-07-19). Прежде контекст писали
трое: `MenuRouter` (штатно), `DeploymentController` (боевая расстановка/тест-зона/старт боя),
`BattleInputController` (Combat при старте боевого скоупа). Теперь оба боевых потребителя зовут
только `SetPhase` — контекст пересчитывает навигатор из фазы. Остаётся один легитимный внешний
писатель `GameplaySuppressed` — dev-консоль QFSW (до её замены своей DevConsole, Трек К).

Следствие: снапшот прежнего контекста (`_prevContext`) не нужен — «восстановить» = пересчитать из
фазы (снапшот протух бы, если фаза сменилась при открытом меню; теперь это невозможно по построению).

## 5. Инварианты `PointerOverUI` (развязка кликов UI ↔ мир)

Screen-space uGUI в проекте нет: HP/мана-бары и цифры урона — world-space Canvas
([[tech/10-reference/scene-sorting|Reference - Scene & Sorting]]), UITK-панель прозрачна
(`clearColor: 0`) и композитится поверх мира. Отсюда работают «дырки»:

- **Ровно один `UIDocument`** на всё игровое UI.
- **Прозрачные корни всегда `pickingMode = Ignore`** (корень инвентаря, слои-контейнеры) — клик
  сквозь них уходит в мир.
- `IInputService.PointerOverUI` = `panel.Pick(pos) != null` — разводит клики: над непрозрачной
  панелью → UI, над «дыркой» → мир. Тот же механизм — основа для будущих live-курсоров партнёров
  (курсор в World-пространстве, если стек пуст/Sheet).

Именно `Sheet` (не глушит геймплей) + `PointerOverUI` дают drag реликвии из грида инвентаря на
юнита арены: панель открыта, но мир под ней жив и кликабелен через дырки.

## 6. Радио-режимы табов и модель пространств

**Табы топбара Карта / Бой / Инвентарь — взаимоисключающие РЕЖИМЫ отображения**, включён ровно
один; таб = «перейти в режим», НЕ тумблер (повтор = уже там = no-op). Бутстрап приводит стек+мир к
режиму тремя идемпотентными переходами: `GoToMap` / `GoToBattle` / `GoToInventory`.
`MenuRouter.HasMapInStack` отличает возврат на карту петли акта (result-экран в стеке) от read-only
карты. Тест-зона и инвентарь — явные идемпотентные интенты (`SetTestZoneRequest(bool)`,
`ShowInventory`/`HideInventory`), не тумблеры.

**Модель пространств:**
- **Мир** — persist-сцена с камерой, ВСЕГДА база; не в стеке навигатора, скрыть нельзя (только
  скин арены тест ↔ обычная через `TestZoneChangedEvent`).
- **Карта** — единственный непрозрачный оверлей (`Page`), закрывает мир.
- **Инвентарь / тест-зона** — прозрачные оверлеи (`Sheet`), мир под ними виден.

Владелец состояния тест-зоны — `DeploymentController` (единственный источник
`TestZoneChangedEvent`); скин арены и Sheet-экран слушают СОСТОЯНИЕ, не бродкаст-тумблер.

## 7. Что снесено и что осталось (реестр костылей)

Снесены в ходе реворка: императивный z-порядок (`BringToFront`/`SendToBack`), флаги-тумблеры
(`_testActive`/`_inventoryOpen`/`_hiddenForTest`/`_menuModeActive`), снапшот контекста, мосты
`HideTopForTest`/`ShowHiddenForTest`, веник `CloseAll` для завершения забега (заменён единой
кооперативной отменой по токену), мультиписатель контекста (K8), легаси `RunTopBarView`/`IRunTopBar`,
мёртвый интерфейс `IMenuRouter`.

Осталось (адресуется в треках, см. план):
- **`Keyboard.current` напрямую** в `DeploymentController.ReadyPressed` (Enter расстановки) — Трек Х.
- **Text-event на Push+Detach** (выбор ≠ закрытие, не `ShowAsync`) — отдельная задача.
- **QFSW-консоль** как второй писатель `GameplaySuppressed` — Трек К (своя DevConsole).

## 8. Открытые хвосты (швы, реализация в треках)

- **Тултипы** (Трек Т) — слой `layer-tooltip` готов; система несущая для жанра.
- **Live-курсоры партнёров** (с мультиплеером) — слой `layer-cursors`; курсор живёт в
  пространстве, не на экране; `ActiveSpace` навигатора + `PointerOverUI`.
- **Тосты / событийный фид / чат** (по запросу) — слой `layer-system`.
- **UI-хоткеи + rebinding** (Трек Х) — режимы M/I/B через UI-карту `InputService`.
- **Своя DevConsole** (Трек К) — Modal-экран навигатора вместо QFSW; убирает последнего внешнего
  писателя контекста.
