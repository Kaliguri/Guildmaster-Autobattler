# Методичка: создание реликвии-юнита

Саб-методичка [[gdd/40-content/authoring/unit|создания юнита]] — специфика **реликвии**.
Читай сначала общую часть (оси, AI-шов, данные), потом это.

Рабочий процесс заполняется по [[gdd/relics/template-relic-card|шаблону карточки]] (шаги
0–7). Референс — [[gdd/relics/the-bulwark|The Bulwark]].

---

## 1. Что такое реликвия

Реликвия — **«чемпион» для «Сосуда»-пилота** (аналогия «игрок в LoL и его чемпион»). Она
несёт **весь боевой кит**: стат-блок, категориальную конфигурацию (тип урона/атаки/ресурса)
и набор способностей. «Сосуд» сам по себе статов не имеет — вся мощь из реликвии
([[gdd/40-content/relics-overview|обзор]]).

Ключевое отличие от врага: реликвия живёт **дольше одного боя** — её прокачивают, между
боями перекидывают на другого «Сосуда», она встраивается в синергии команды.

---

## 2. Две оси классификации (не путать)

| Ось | Значения | Что задаёт |
|---|---|---|
| **Редкость** | Треш / Обычная / Уникальная | **размер кита** (0–1 / базовый / расширенный) и шанс дропа. НЕ множитель статов |
| **Тип** | Стандартная / Проклятая / Божественная | побочные эффекты для «Сосуда» (Проклятая — штрафы на забег; Божественная — бонусы, только из ивентов) |

Полная модель — [[gdd/40-content/relics-overview]]. Обе оси независимы: «Обычная» — только
редкость, «Стандартная» — только тип.

---

## 3. Процесс (шаги карточки)

Идёшь по [[gdd/relics/template-relic-card|шаблону]] сверху вниз — от замысла к деталям:

| Шаг | Суть | На что смотреть |
|---|---|---|
| **0. Заголовок** | Имя по системе Арканы `The [X] (Класс)` | наименование — см. §5 |
| **1. Общая инфа** | Редкость, Тип, Ресурс, дальность | ресурс задаёт, есть ли мана-активки |
| **2. Зачем нужна** | Фантазия, Роль, Отличие от тира | **отличие** обязателено — иначе дубль |
| **3. Статы** | Крупными мазками (не числа) | числа — на сборке SO, в карточке словесно |
| **4. Базовая атака** | Дальность/доставка, школа, паттерн | школа — на **каждую** атаку отдельно |
| **5. Навыки** | Обычная = **2**; уник — больше | активный (AI кастует) / пассивный |
| **6. Улучшения** | 6 = T1×3 + T2×3 | → отдельная методичка, см. §4 |
| **7. AI-настройки** | Поднабор блоков A–G | словарь — [[gdd/relics/ai-settings-model]] |

---

## 4. Улучшения (Шаг 6) — отдельная методичка

Улучшения проектируются по своей модели (6 = идеи + одиночки, под комбинирование). Не
дублирую здесь — полностью в [[gdd/40-content/authoring/relic-upgrades|методичке улучшений
реликвий]]. Из неё же — чеклист комбинируемости и разбор Bonewright/Pyre.

---

## 5. Специфика, которой нет у врага

- **«Сосуд»-носитель.** Реликвия проектируется в отрыве от пилота: Судьба и перки «Сосуда»
  — отдельный слой ([[gdd/40-content/relics-overview|§Сосуды]]), кит их не дублирует.
- **Синергия в ростере.** Сильная реликвия цепляет команду по модели `producer → consumer`
  (яд Bonewright → «Взрыв спор» Bloom). Проверь: что она **даёт** команде и что **потребляет**.
- **Ресурс.** Если есть активка на мане/ярости — ресурс должен быть задан в Шаге 1, иначе
  ману-зависимый текст мёртв (был баг Pyre). Половина ростера — `Ресурс: нет`, учитывай
  при кросс-реликвийных эффектах (руна ресурса Runesmith).
- **Наименование — система Арканы:** `The [X] (Класс)`, EN-канон, id `relic.*`. Карточки —
  Обычные vs Уникальные (Старшие арканы).
- **Уникам можно >2 навыков** (Старший аркан богаче), Обычным — ровно 2.

## 6. Чеклист реликвии (сверх общего)

- [ ] Пройден общий чеклист [[gdd/40-content/authoring/unit|юнита]]
- [ ] Редкость и Тип заданы (две разные оси)
- [ ] Шаг 2 «Отличие от тира» отвечает, зачем она **сверх** существующих
- [ ] Навыки: 2 для Обычной (>2 только уник); каждый помечен активный/пассивный
- [ ] Ресурс согласован с активками
- [ ] Есть внешняя синергия (что даёт / что потребляет команда)
- [ ] Улучшения — по [[gdd/40-content/authoring/relic-upgrades|методичке]] (если делаются)
- [ ] Имя по системе Арканы; id `relic.*`; loc-ключи (RU)
- [ ] Карточка заведена в [[gdd/relics/index|каталог реликвий]]
