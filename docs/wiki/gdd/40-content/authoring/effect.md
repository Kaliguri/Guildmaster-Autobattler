# Методичка: создание эффекта

Как проектировать **эффект** (статус) и как оформлять его в документации. Эффект — базовый
кирпич глубины: киты реликвий и врагов собираются из producer→consumer связок вокруг
эффектов ([[gdd/20-combat/effects|каталог эффектов]]).

Технический движок (`EffectData`, `IEffectComponent[]`, диспел) — [[tech/10-reference/combat-model|Combat
Model §5]]. Здесь — **дизайн и авторинг**.

---

## 1. Что такое эффект

**Эффект — это глагол.** Идентичность несёт статус, урон-число вторично: «огненный герой» —
не «красный урон», а «накладывает и эксплуатирует горение». Технически эффект — это
`EffectData`: набор **тегов**, **правило стакинга**, **тир снимаемости** и **компоненты**
(`ЧТО он делает`), параметры которых скейлятся статами.

> **Producer→consumer** (кто накладывает / кто эксплуатирует) — ядро глубины, но в
> ГД-доках **НЕ ведётся**: это выводится движком (накладыватель = у кого компонент
> `ApplyEffect`; потребитель = reactive на тег). Ручной реестр носителей рассинхронится —
> [[gdd/00-meta/journal-adr|решение 2026-07-17]].

## 2. Расслоение: карточка или сборник

Пул эффектов разнокалиберный — от «Отравления» с целой под-системой до «−10% дальности».
Поэтому две формы записи:

| Форма | Для чего | Пример |
|---|---|---|
| **Карточка** (отдельная страница) | Тяжёлые/уникальные эффекты | Отравление, Поджог+Угли, Сон, Метка |
| **Сборник** (страница-список) | Простые однотипные эффекты | Стат-модификаторы, CC-примитивы, комбо-правила, теги-состояния |

### Критерий: когда эффект заслуживает своей карточки

Своя страница, если есть **хотя бы одно**:
- **(а)** уникальное правило поверх стат-мода (Сон спадает от урона + ×2 пробуждение);
- **(б)** несколько под-механик/параметров (Поджог + отдельные «Угли» + детонация);
- **(в)** свой комбо-хук (эффект — часть взаимодействия тегов).

Иначе → в сборник. «Оглушение», «−дальность», «+броня» проходят в сборник автоматически;
«Отравление», «Метка», «Инвиз» — карточки. Правило снимает споры «а это карточка?».

### Сборники (стартовый набор)

- **Стат-модификаторы** — баффы/дебаффы статов (−атака, +броня, ускорение КД, уязвимость…).
- **CC-примитивы** — Оглушение / Обездвиживание / Замедление (+ Заморозка как композит).
- **Комбо-правила** — Раскол / Детонация / Проводимость и т.п. (матрица взаимодействий).
- **Теги-состояния** — Мокрый / Наэлектризованный / Подожжённый / Обмороженный (маркеры).

> Не сваливай всё в один файл — дроби сборники по классу. Разрастётся — дели дальше.

## 3. Тех-поля — это ГД-инфа (прописывать явно)

Эффект **определяется** своими тех-полями — для дизайнера это не «реализация», а дизайн.
Прописывать в каждой карточке/строке сборника:

| Поле | Значения | Почему ГД-решение |
|---|---|---|
| **Класс** | DoT / CC / Бафф / Дебафф / Триггер | что это по сути |
| **Полярность** | Buff / Debuff | диспел и иммунитет фильтруют по ней |
| **Теги** `EffectTag` | Control / DoT / Heal / Shield / контентные (`Frozen`, `Marked`…) | склейка producer↔consumer и AI-фильтры |
| **Стакинг** | None / Stack / Refresh / StackAndRefresh + `MaxStacks` | Поджог обновляется, «Угли» стакают — разный фил |
| **Снимаемость** | `CleanseTier` (T1–T3) / `Unremovable` | тир диспела = баланс (T3 — привилегия уников) |
| **Компоненты (тип)** | periodic (тик) / reactive (событие) / statmod | как эффект действует |
| **Школа/сродство** (для урона) | физ/стих/True · Яд/Свет/Тьма | под какую броню бьёт DoT |

Числа (урон/тик, длительность, пороги) — **словесный ориентир** в карточке; точные значения
на баланс (Фаза 4+), как в карточках реликвий.

## 4. Наименование, id, связь с данными

- **Имя:** RU + **EN-канон** (Отравление / `Poison`, Поджог / `Burn`, Раскол / `Shatter`).
- **id:** `effect.<name>` для эффектов, `combo.<name>` для комбо-правил. Стабильный,
  не переименовывается после релиза ([[tech/10-reference/data-layer]]).
- **Карточка эффекта = источник дизайн-правды; `EffectData`-ассет её реализует** (не
  наоборот). Один `id` — якорь между дизайном и данными.
- Loc-ключи по конвенции (`{id}.name`, `{id}.desc`), **RU заполнен**.

---

## 5. Комбо и теги-состояния

Взаимодействия (Раскол, Детонация, Мокрый+молния…) живут **не** на страницах отдельных
эффектов, а в **сборнике комбо-правил** (матрица «состояние × триггер → эффект»). Карточка
эффекта только **ссылается** на матрицу в шаге «Комбо». Иначе взаимодействие размажется по
4 страницам и рассинхронится.

Теги-состояния (Мокрый и пр.) — лёгкий класс маркеров: у каждого в сборнике две строки
«**что накладывает**» и «**что читает**» — это не producer/consumer-реестр, а само
определение тега (без них тег пуст).

## 6. Чеклист эффекта

**Карточка (большой эффект):**
- [ ] Прошёл критерий §2 (уникальное правило / под-механики / комбо-хук)
- [ ] Заполнены тех-поля §3 (класс, полярность, теги, стакинг, снимаемость, компоненты)
- [ ] Для DoT — школа/сродство и контра указаны
- [ ] Комбо/теги — ссылкой на матрицу, не расписаны на месте
- [ ] Имя RU+EN, id `effect.*`, loc-ключи (RU)
- [ ] Заведён в [[gdd/20-combat/effects|индекс эффектов]]

**Сборник (простой эффект):** строка с классом, тегом, стак-правилом, тиром клинза +
краткое описание. Без отдельной страницы.
