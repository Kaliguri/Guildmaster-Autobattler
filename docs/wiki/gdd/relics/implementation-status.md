# Реликвии: что в движке, что на бумаге

Этот док отвечает на один вопрос: **какая реликвия существует в игре, а какая только описана.**
Дизайн реликвий тут не живёт — он в карточках; редкость и типы — в [[relics-overview|Content - Relics]].

## Как читать статус

Владелец факта — **поле `impl` в шапке самой карточки**, здесь только сводка. Три значения:

| `impl` | Значит | Что можно делать |
|---|---|---|
| `engine` | есть рабочий ассет `RelicData`, механики соответствуют карточке | правки — через баланс-петлю, карточку и ассет менять вместе |
| `partial` | ассет есть, но **механика расходится с карточкой** | расхождение описано в `impl_note`; чинится заходом реализации |
| `paper` | ассета нет вовсе | переписывать свободно, в игре ничего не сломается |

Поле `asset` — id ассета-владельца (`relic.assassin`). У `paper` его нет и быть не должно.
Порядок в дереве: `engine`/`partial` — `order` 10–499 · [[gdd/relics/divider-theory|разделитель]] 500 ·
`paper` — 510+ · инкубаторы идей — 900.

**Мерка сверки:** наличие ассета в `Assets/_Project/ScriptableObjects/Relics/`. Ручная сверка —
2026-07-29 (10 из 21 карточки в движке).

## В движке

```dataview
TABLE impl AS "Состояние", asset AS "Ассет", impl_note AS "Расхождение"
FROM "gdd/relics"
WHERE impl = "engine" OR impl = "partial"
SORT order ASC
```

## Только дизайн

```dataview
TABLE combat_class AS "Класс", status AS "Статус дока"
FROM "gdd/relics"
WHERE impl = "paper"
SORT file.name ASC
```

## Долг сверки карточка ↔ движок

Три расхождения известны из handoff и продублированы в [[gdd/00-meta/roadmap|Meta - Roadmap]]
§Реликвии и юниты. **Кодом они не пересверены** (дата handoff раньше нескольких коммитов) —
у карточек стоит `impl: partial` именно с этой оговоркой:

- [[gdd/relics/the-bloom|The Bloom]] — споры не лечат;
- [[gdd/relics/the-pyre|The Pyre]] — воспламенение без стаков, поджог плоский;
- [[gdd/relics/the-thorn|The Thorn]] — шипы без роста радиуса.

Пересверка — заход контуров `data-authoring` / `combat-sim`; после неё статус либо становится
`engine`, либо расхождение уточняется.

## Ассеты без карточки

`relic.base` — служебный базовый ассет (`BaseRelic.asset`), от которого наследуются числа.
Карточки не имеет и не должен: это технический носитель дефолтов, а не контент.
